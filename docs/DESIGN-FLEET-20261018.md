## 1. 지켜야 하는 사실

| 사실 | 화면 규칙 |
|---|---|
| 실제로 연결되는 로봇은 **하나**(`useLink` 하나, provider `simulation_gate`/`go2_direct`) | 연결 로봇만 `연결됨` 꼬리표. 계획 로봇은 `계획` |
| 계획 로봇 목록(API `robots`) ≠ 실기 연결 | 계획 로봇에 STOP·조종·영상 자리 없음 → «연결 없음 · 명령이 가지 않습니다» |
| API `analyze` = **2D 기하 검토**(경로 길이·막힌 구간·연결 없는 점·같은 배치안 경로 교차). `note` = «2D 기하 검토 — 물리·넘어짐·실제 도달 판정 아님» | 표 머리에 그 `note` 원문. 도달·넘어짐은 «미측정» |
| API 가 **주지 않는 값**: 예상 시간, 센서 범위·사각, 시각 기준 로봇 간섭 | 화면에 그 행·레이어 **없음**(계산값 사칭 0). 나중에 API 가 주면 추가 |
| `export` = 저장본에서 `world.sdf`·층 지도·plan.json ZIP 만들기(파일 생성만, 기동 0) | «세계·지도 묶음 내보내기» 단추 = API 동작 시 켬. Gazebo 기동 단추 없음 |
| `go2_direct` 는 `command=false` (CONTRACT.md:95-97) | 실기 대상 조종 자리에 «조종 미지원 · 보기 전용» |
| 계단 확인 치수 미확인(API 경고 `stairs_range_unverified`), 라이다 L1/L2 미정(`lidar_spec_unconfirmed`), 로봇 모델 `generic_proxy_not_gait` | API 경고를 그대로 보인다. 값을 확정처럼 꾸미지 않는다 |
| 조종권 회수 규칙 미정 | 회수 단추 없음. «회수 규칙 미정» 한 줄 |

## 2. 모드: «리허설» 과 «현장 관제»

PC `#/Fleet` 머리줄 가운데 두 칸 전환 단추. **모드가 화면 자료의 뜻을 정한다.**

| | 리허설 | 현장 관제 |
|---|---|---|
| 뜻 | 저장된 프로젝트의 배치안 보기·비교. 실제 로봇 없음 | 지금 연결된 로봇 상태 + 고른 배치안(따로 보기, 좌표 정합 미확인) |
| 머리 띠 | `--paper-2` + 위 **점선** `--rule` 2px · «리허설 · 계획과 2D 기하 검토만, 로봇에 명령이 가지 않습니다» | `--dim-soft` + 위 **실선** `--brand` 3px · «현장 관제 · 연결 {n}대({시뮬/실기})» |
| 로봇 | 모두 점선 · `계획` | 연결 = 실선 + `연결됨 · 시뮬/실기`, 계획 = 흐린 점선 + `계획` |
| 오른쪽 판 | 배치안 비교 | 경고 모음 + 실측 궤적 패널 |
| STOP | 계획 카드엔 없음. 기존 전역 STOP·Space(`useStopKey`)는 **모드와 무관하게 그대로** | 연결 카드마다 STOP = `stopNow()` |

- 기본 모드: `linkOk` 면 현장 관제, 아니면 리허설. 사용자가 바꾼 값은 `localStorage` 편의 기억(try/catch, 실패 시 기본값).
- 색: 리허설에 경고색 안 씀. 점선 = 계획, 실선 = 연결·실제. 빨강은 STOP·차단만.

### 3-2 로봇 카드 (`FleetRobotCard`, 높이 고정)

**연결 로봇:** 기존 `headChips()`(status.tsx:16) 결과 **4개(시뮬·연결·역할·잠금)를 줄이지 않고 그대로** 보인다. «가장 높은 원인 + 외 N» 요약은 하지 않는다(잠금·조종권을 숨기지 않기 위해). 순서도 기존 반환 순서 그대로, 새 순위 0.

| 줄 | 연결 로봇 | 계획 로봇 |
|---|---|---|
| 1 | 표지 R1 · 이름 · `연결됨 · 시뮬` | 표지 · `robot.name` · `계획` |
| 2 | 기존 칩 4개(Chip, 2×2) | 층 · 출발 자세 |
| 3 | 영상 칩(기존 `camChip`) | 배치안 경로 길이 `length_m` + `기하` |
| 4 | «조종권 회수 규칙 미정» | 경고 수(막힘·연결 없음·교차) |
| 단추 | `조종 화면` → `#/Main` · `STOP`(오른쪽 끝) | `지도에서 보기` / «연결 없음 · 명령이 가지 않습니다» |

- 연결 로봇과 계획 로봇의 짝짓기(어느 계획 로봇이 지금 연결된 그것인지)는 **사용자가 고른다**(`이 연결을 R1 로 보기` 선택). 자동 짝짓기 0. 고르기 전에는 연결 로봇 카드가 따로 맨 위에 있다. **짝지어도 이름표만 같아질 뿐 좌표 정합은 아니다** — 카드에 «좌표 정합 미확인».
- «전체 STOP» 은 연결 2대 이상일 때만(지금 0 — 만들지 않음).

### 3-3 지도 레이어

| 레이어 | 근거 자료 | 그림 | 기본 |

| 막힌 구간·연결 없는 점 | `analyze.routes[].blocked_segments`/`unreachable_points` | 해당 선분 `--note` 굵게, 점에 ▲ | 리허설 켬 |

### 3-4 오른쪽 판 — 리허설: 배치안 비교 (`PlanCompare`)

열 = `scenarios`(≤12, 넘치면 가로 스크롤). 행은 **API 가 주는 것만**:

|---|---|---|
| 로봇 수 | `scenario.robots.length` | `계획` |

### 3-5 오른쪽 판 — 현장 관제

- 위: 경고 목록(기존 `MAlerts` 자료·구분 그대로) + 앞에 로봇 표지.
- 아래: **«실측 궤적» 별도 패널** — 연결 로봇의 기존 `trail`·위치를 실행 중 지도 좌표(기존 live map)로만 그린다. 머리에 «좌표 정합 미확인 · 계획 지도와 겹치지 않습니다». 계획과의 최근접·이탈 거리·지남 여부 계산 0, 도착 시각·지연 0.
- 계획 vs 실제 비교·메모는 world/TF 결속이 생긴 뒤(715·API 결정)로 보류. 그 전에는 단추·표를 만들지 않는다.

### 4-2 도구 ↔ API 타입

| 도구 | API | 속성 칸 | 서버 형식 범위(API §4) |
|---|---|---|---|
| 벽 | `Wall` a·b·thickness·height | 길이(a–b) · 두께 · 높이 m | 길이 ≥0.05 · 두께 0.05–1.0 · 높이 0.05–10 |
| 상자 | `Box` center·size·yaw | 가로·세로·높이 · 회전° | 각 변 0.05–50 |
| 계단 | `Stairs` floor→to_floor(바로 위층)·start·yaw·steps·riser·tread·width | 단 수 · 단 높이 · 디딤 · 폭 · 방향 | 단 수 2–40 · 단 높이 0.05–0.25 · 디딤 0.15–0.60 · 폭 0.5–4.0 · `steps×riser` = 층 높이 차(±0.005) |
| 층 | `Floor` id·name·z·height | 이름 · 바닥 z · 층 높이 | 1–8, z 오름차순, 첫 층 0 |
| 로봇 | `Robot` name·floor·pose(x,y,yaw)·model `go2_proxy` | 이름 · 층 · 자세 | ≤12, id ≤24자 |
| 센서 | `Sensor` kind·mount(x,y,z,yaw, 로봇 기준) | 종류 `lidar_l1`/`lidar_l2`/`lidar_unknown`/`camera`/`depth` · 붙는 위치 | 로봇당 ≤6. **로봇에만 붙음**(고정 센서는 장비 `camera_fixed`) |
| 장비 | `Equip` kind·floor·pose·label | 종류 `camera_fixed`/`relay`/`marker`/`other` · 라벨 | ≤200 |
| 경로 | `Route` robot·floor·points | 로봇 · 점 찍기(2–200) | ≤48 |
| 배치안 | `Scenario` name·robots·routes | 이름 · 포함 로봇/경로 체크 | ≤12. 경로의 로봇이 배치안에 있어야 함 |
| 도면 | `Background` mime·data_b64·floor·ref_px·ref_m | 투명도(화면 전용) · 잠금 | PNG/JPEG, 디코드 ≤192 KiB, ≤4096 px. **UI 가 줄이고 압축**(서버는 자르지 않음) |
| 축척 | `ref_px` ↔ `ref_m` 두 쌍 | 도면 위 두 점 → 실제 좌표 입력 | 축척 전엔 벽 길이 칸 «도면 축척 안 맞춤» |

- 숫자 입력은 서버 범위를 화면에서도 막는다(입력 편의). **계단 범위는 형식 상한일 뿐 오르기 확인 범위가 아니다** — 계단 속성 판에 항상 «Gazebo 오르기 확인 치수 미확인» 꼬리표.
- 센서 종류 옆 «라이다 기준 L1/L2 미정 · 사양 미확인». 로봇 속성 옆 «보행 검증 아님(generic proxy)».
- 도면은 우리 서버 저장소에만 들어간다(외부 업로드 0). 내보내기 ZIP 에는 sha256 만.

### 4-3 저장·충돌 (API `put`)

- 새 프로젝트 `put id:null`, 고치기 `put id, rev`(내가 본 판).
- **409 판 충돌:** 초안은 그대로 두고 «다른 곳에서 r{cur.rev} 가 저장됨 · 내 초안은 남아 있습니다» + `서버 판 열어 비교`(다른 탭) · `내 초안으로 새 판 저장(서버 판 위에)`(사용자가 고른 뒤에만 rev=cur.rev 로 재전송). 자동 덮어쓰기 0.
- 400 issues = 캔버스 위치 표시(`at`·`floor`) + 목록. 413/507/409 상한 = 원문 한국어 `error` 그대로.
- 브라우저 쪽 초안 보존은 기존 `data/editor.tsx`·`scratch` 규칙(실패 어느 경우에도 초안 삭제 0). 저장 전 화면 이탈 시 기존 dirty 경고.
- 연타: 저장 중 단추 꺼짐(busy). 늦게 온 옛 응답은 `gen` 비교로 버림.

- 구현 범위에 **JSON 파일 가져오기·내보내기와 되돌리기/다시 하기**를 포함한다(root 최초 요청 · `../UI-DECISIONS.md` 5절이 정본: 손상·누락·모르는 판 거부 + 현재 편집 유지, Ctrl+Z / Ctrl+Shift+Z·Ctrl+Y, 입력칸 포커스 중 단축키 무시, Space 는 전역 STOP 그대로).

### 4-4 검토 (API `analyze`, 초안 scene 그대로)

- `검토` 단추 = `analyze {scene}`. 결과 `issues`(error ■ / warn ▲) 목록, 누르면 그 위치로.
- 화면 글: `analyze.note` 원문 + «저장은 error 가 없을 때만 됩니다(warn 은 저장됨)».
- 클라이언트 자체 검사는 입력칸 범위 정도만. 겹침·경로 판정은 서버 결과만 쓴다(같은 기하 한 곳).

### 4-5 묶음 내보내기 (API `export`)

| 조건 | 단추 |
|---|---|
| API 동작 + 저장본 있고 초안 변경 없음 | 켬 · «세계·지도 묶음 내보내기 (r{rev})» → ZIP 내려받기(base64 → Blob) + 파일 이름·sha256·크기 표시 |
| 저장 안 한 변경 있음 | 꺼짐 · «저장한 판만 내보냅니다 · 먼저 저장» |
| API 없음/실패 | 꺼짐 · «리허설 서버 응답 없음({code})» |
| 413 | «내보내기 파일이 640 KiB 를 넘습니다» 원문 |

- 내려받은 뒤 안내 한 줄: «이 묶음은 파일입니다 · Gazebo 기동은 사용자가 합니다 · 계단 치수·보행은 검증 전». 시뮬 시작 단추는 여기 만들지 않는다(기존 `#/PcMap` 경로는 기존 지도만).
