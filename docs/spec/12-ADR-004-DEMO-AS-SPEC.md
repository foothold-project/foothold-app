# ADR-004 — 시연 판을 화면 정본으로, 보이는 기능 전부 구현

| 항목 | 내용 |
|---|---|
| 문서 번호 | FH-SPEC-12 (ADR-004) |
| 상태 | **초안**. §1 의 확정 줄은 제품 책임자 지시 그대로 옮긴 것이고, 제안 줄은 확인이 필요하다 |
| 작성일 | 2026-11-28 |
| 관련 | [09 ADR-002](09-ADR-002-PHONE-DIRECT.md) · [10 ADR-003](10-ADR-003-OPERATOR-APP-TOWER-WEBSIM.md) · [08 작업 방식](08-DEV-PROCESS.md) · 진행표 이슈 #526 |

표기는 [00 §2](00-README.md#2-문서-규칙)를 따른다. **확정** = 제품 책임자 지시 (날짜), **제안** = 작성자 제안 (확인 필요), **미결** = §5.

## 1. 결정

1. **시연 판 (폰 가로 844×390 · PC 1920×1080, 화면 97 장) 이 화면 정본이다.** 화면에 보이는 기능은 하나도 빠짐없이 실제 앱에 붙인다. 어두운 판과 밝은 판을 모두 둔다. (확정 2026-11-28 04:02 · 04:08 목표)
2. **PC 탭은 관제 · 로봇 · 지도 · 임무 · 기록 · 설정 여섯이다.** ADR-003 의 «시뮬» 탭은 따로 두지 않는다. 시뮬은 임무 탭의 «예행» (배속 모의 실행) 과 로봇 탭의 시뮬 로봇으로 들어간다. (제안. 근거: 시연 판 u4 · u5 · u6 과 요구 원장 U0 탭 줄)
3. **걷기 모드는 Classic · Sport · START · AME-2 넷이다.** 멈춰 있을 때만 바꾸고, 바꾸기 전에 확인을 한 번 받는다. PC 단축키는 Shift + 1 ~ 4 다. AME-2 는 정책 파일이 오기 전까지 «준비 안 됨» 으로 둔다. (확정 11/28 03:30 · 04:02 「Sport 모드도 둔다」, 계약은 #525)
4. **로봇이 보이는 모든 자리는 지금 동작을 그대로 그린다.** 임무 중이면 걷고, 충전 중이면 엎드린다. 실제 앱은 각 로봇이 실제 지도 위에서 하는 임무를 시뮬 화면으로 실시간 보여 준다. (확정 11/28 03:1x)
5. **지도는 외부 큰 부지와 건물 안 여러 층을 둘 다 둔다.** 첫 실내 건물은 `공정동 A` (3 층, 점검 지점 16) 다. 층 이동은 첫 판에서 위층 계단참으로 다시 시작한다 (순간 이동). 계단 보행은 MuJoCo 시험 뒤에 판단한다. (확정 11/28 04:02 「내부 건물 안 순찰 · 아주 디테일하게」, 층 이동은 제안)
6. **PC 키보드 조종: ↑ · W 는 앞으로, ← → · A D 는 제자리 돌기, ↓ · S 는 막힘, Space 는 정지.** 지금 dev 와 같다. 옆걸음 키는 없다. (제안. 옆걸음 키를 따로 둘지는 §5)

## 2. ADR-003 에서 바뀌는 줄 (확인 뒤 적용)

| ADR-003 | 지금 | 바뀌는 것 |
|---|---|---|
| §1 결정 3 | 실기 조종은 폰만 · PC 는 시뮬 탭 | PC 로봇 탭에서 실기 조종과 정지 (시연 판 u4_1 · u4_9). **안전 범위**라 08 §3 의 두 모델 검토와 셀프테스트 관문을 거친다. §5 결정 필요 |
| §3 | 총괄은 실기 조종 안 함 | 요구 원장 U4-16 · U9-10 · U2-05 는 총괄도 자기 로봇을 붙이고 조종한다. §5 결정 필요 |
| §4 | PC «시뮬» 탭 | 임무 «예행» 과 로봇 탭 시뮬 로봇으로 옮긴다 (§1 결정 2) |

## 3. 진행

- 진행표는 이슈 #526 하나다. 원장 210 줄을 dev 와 대조한 결과는 있음 24 · 일부 77 · 없음 99 · 미확인 10 이다 (11/28, 코드만 읽음).
- 담당: 웹 (apps/web) 은 app-design-lx, 서버 · 에이전트 · 계약 · 시뮬은 app-lx. 계약이 먼저 PR 로 나가고, 화면은 생성된 TS 를 쓴다 (08 §1).
- 줄 하나를 끝내면 시험을 통과한 뒤 별도 검수 세션 (코드 · 레이아웃 · 사용자 흐름 · 정보 겹침) 을 거쳐 체크한다.
- 빌드 · 시뮬 · 실폰 · 실로봇 확인은 서로 대신하지 않는다. 실기 실행은 제품 책임자의 직접 확인 뒤에만 한다.

## 4. 하지 않는 것

- 계약 없이 화면에서 새 명령을 만들지 않는다.
- 안전 셀프테스트 기대값을 바꿔서 통과시키지 않는다 (08 §3).

## 5. 미결 (제품 책임자)

| 항목 | 막는 일 |
|---|---|
| PC 실기 조종 · 정지 허용 (ADR-003 §1 결정 3 대체) | 로봇 탭 조종 |
| 총괄 계정의 실기 조종 · 정지 · 붙이기 | U4-16 · U9-10 · U2-05 |
| 임무 시작 · 일시정지 · 이어 가기를 서버 길로도 둘지 (지금은 폰 직결만) | 임무 탭 실기 실행 |
| 실내 월드 걷기 확인을 MuJoCo 로 할지 (simmgr 는 Gazebo 기동 구조) | 실내 지도 시뮬 |
| 옆걸음 키를 따로 둘지 | 키보드 안내 |
| 로고 기울기 3 도 (지금 v1) 인지 5 도인지 | 브랜드 |
| 서버가 끊겼을 때 폰 직결 정지를 살릴지 (시연 판 u1_8 은 정지가 회색) | 폰 정지 |
