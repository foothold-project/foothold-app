## 1. 결정 (요약)

1. **앱을 둘로 나눈다.** 현장 운영 관리자의 **폰 조종 앱**(로봇 1대를 실시간으로 다룸)과 총괄의 **총괄 웹**(여러 대 상태·결재·배정·기록, 실시간 조종 없음).
2. **실시간 조종은 폰 ↔ 로봇 직결.** 조이스틱·STOP·카메라는 현장 망에서 로봇 안 연결 서버(에이전트)로만 오간다. 관제 서버·클라우드는 조종 경로에 없다.
3. **기록은 로봇이 서버로 보낸다.** 로봇이 먼저 자기 안에 저장하고, 인터넷이 되면 서버로 직접, 안 되면 폰을 거쳐, 둘 다 안 되면 쌓아 뒀다가 보낸다.
4. **총괄 웹에는 STOP 단추를 두지 않는다.** 대신 «정지 요청»을 보내면 담당자 폰에 알림이 간다. 웹은 로봇에 즉시 닿는 경로가 아니라서, 누르면 멈춘다고 보장할 수 없는 단추를 두지 않는다.
5. **시뮬은 Gazebo 먼저, MuJoCo 로 교차 확인. 앱용 시뮬에 Isaac Sim 은 쓰지 않는다.** 시뮬 로봇도 실기와 같은 연결 서버 계약을 쓰므로 폰은 시뮬인지 실기인지 몰라도 된다.
6. **안전 규칙은 그대로다.** STOP 래치, 자동 재개 없음, deadman 0.3 s, 로봇마다 조종자 한 명. 새로 하나 더한다: 조종자 폰이 끊기면 자율 실행도 멈춘다(§7).

## 2. 배경

- 팀 설계 문서(2026-10-19 앱 가이드)가 정한 방향: 앱은 «컨트롤 앱(한 대, 우선)»과 «컨트롤 타워 웹(여러 대, 다음 순위)» 둘이고, 실시간 조종은 현장 로컬망에서 로봇 안 연결 서버로만 한다. 타워는 상태·지도·기록만 받는다.
- 제품 책임자 결정(2026-10-20~21):
  - 총괄은 떼서 별도 창(웹)으로 만든다.
  - 폰은 1인 1대. 한 폰이 두 대의 조종권을 갖지 않는다.
  - Unitree 기본 앱과의 차별점: 시뮬에서 지도를 고르고 만들 수 있고, 미리 만든 시나리오대로 로봇을 움직인다.
  - 돌발 상황에는 사람이 끼어든다. 불 → 시나리오 중단. 넘어짐·물 고임 → 사람이 처리한 뒤 «이어서». 장애물 배치가 바뀐 정도는 Nav2 가 처리한다.
  - 앱용 시뮬은 Gazebo·MuJoCo 만(팀장 승인). Isaac Sim 은 외부 사용자에게 서버로 제공하면 별도 유료 라이선스가 필요하다. Gazebo·MuJoCo 는 Apache 2.0, Go2 모델(unitree_ros·unitree_mujoco)은 BSD-3.
- 2026-10-19 기획(01~06)은 «화면 → 관제 서버 → 에이전트» 중계 구조였다. 이 ADR 이 그 구조를 바꾼다(§9).

## 3. 폰 조종 앱

### 3.1 흐름
```
로그인 → 로봇 연결 → 조종 → 끝내기(조종권 반납)
```

### 3.2 화면
| 화면 | 하는 일 |
|---|---|
| 로그인 | 관제 서버 계정으로 로그인. 로봇 연결용 출입증을 받는다(§5). |
| 로봇 연결 | 위: 실기 목록(주변에 없으면 «찾는 중»). 아래: **시뮬 로봇 띄우기** — 지도(월드) 고르기, 시뮬러 Gazebo/MuJoCo, «빈 공간에서 지도 만들기». 다른 사람이 조종 중인 로봇은 «보기만». |
| 조종 (가로) | RGB 카메라 전체 화면, 왼쪽 조이스틱 = 앞뒤·옆(vx·vy), 오른쪽 = 회전(wz). 왼쪽 위 상태(배터리·지연·정책·**시뮬** 표시), 오른쪽 위 STOP(늘 보임, 64 px 이상), 아래 줄 [자세] [시나리오] [지도·목표] [정책]. |
| 지도 만들기 | 조이스틱으로 돌며 SLAM → 저장 → 총괄 웹에 승인 요청. |

조종 화면 아래 줄은 화면을 바꾸지 않고 **시트**로 연다.
| 시트 | 하는 일 |
|---|---|
| 자세 | 서기·앉기·넘어진 뒤 일으키기 |
| 시나리오 | 이 로봇에 배정된 시나리오 고르기 → 실행 전 점검 → 진행 표시. 조이스틱을 만지면 일시정지, «이어서»는 사람만, «중단» |
| 지도·목표 | 지도 위 점·방향을 찍어 보내기 → 이동 중·도착·실패. 갈 수 없는 목표는 «할 수 없음» |
| 정책 | 지금 보행 정책 표시. 전환은 로봇이 선 뒤에만 |

### 3.3 조이스틱 범위
- 로봇이 «허용 범위표»를 보내고, 폰은 그 범위로 자른다. 잘리면 «명령 범위 조정»을 보인다.
- 허용 범위는 **확인된 명령 집합**으로 제한한다. 현재는 정지·전진 0.6 m/s·전진과 회전 ±0.5 rad/s 조합 4개, 옆·뒤 0이다. 2026-10-22 제품 결정은 저속 후진(최대 0.2 m/s)·제자리 회전·속도 3단 추가이며, 실제 보행 확인 전에는 열지 않는다. 폰은 보통(0.6) 기본, 느림·빠름 선택 불가와 "시뮬에서 아직 확인 안 됨"을 표시한다. 확대는 08 §3 두 모델 안전 검토를 거친다.

## 4. 총괄 웹

| 메뉴 | 하는 일 | 2026-10-20 dev 와의 관계 |
|---|---|---|
| 로봇 | 여러 대 목록: 상태·위치·배터리·정책·현재 시나리오·담당자·**마지막 수신 시각**. 시뮬 로봇은 «시뮬» 표시. 로봇마다 «정지 요청» | 관제 화면을 바꾼다 |
| 결재 | 담당자가 올린 지도·시나리오 배정 승인/반려 | 결재 화면 그대로 |
| 시나리오 | 임무·시나리오 편집, 로봇·담당자 배정 | 임무 화면 그대로 |
| 지도 | 목록·편집·판 비교. 시뮬 월드와 짝 | 지도 화면 그대로 |
| 기록 | 주행·STOP·넘어짐·개입·정지 요청 | 기록 화면 그대로 |
| 설정 | 계정·역할 | 설정 화면 그대로 |

- **조종 탭은 웹에서 뺀다.** 실시간 조종은 폰 앱만 한다.
- 머리줄 STOP 은 3단계(§8)에 «정지 요청»(§5.3)이 생길 때 뺀다. «정지 요청»은 기록에 남고 담당자 폰에 알림으로 간다. 폰이 받았는지, 로봇이 멈췄는지는 «마지막 수신 시각»과 함께 상태로 보인다.

## 5. 연결 구조

```
  [폰 조종 앱] ──현장 망 WS (조종·STOP·상태)──▶ [로봇 안 에이전트 = 연결 서버] ──▶ 안전 Core ──▶ 보행 정책
       │      ◀──현장 망 (카메라 영상)──────────        │
       │                                              │ 기록·상태 (먼저 로컬 저장)
       │ 로그인·시나리오 목록·알림                      ▼
       └──────────────────────────────▶ [관제 서버] ◀── 인터넷 직접 / 폰 거쳐 / 나중에
                                             ▲
                                  [총괄 웹] (보기·결재·배정, 실시간 조종 없음)
```

- **카메라:** 1단계는 에이전트가 낮은 빈도 JPEG 프레임으로 보낸다. WebRTC(H.264 하드웨어 인코딩)는 실기 단계에서 정한다.
- **기록 보내기:** 사건마다 고유 ID 를 붙여 서버는 한 번만 저장한다. 작은 사건 먼저, 큰 파일은 나중. 총괄 웹은 «마지막 수신 시각»을 함께 보여 준다.
- **현장 망 주의:** HTTPS 로 연 웹 페이지는 현장 로봇의 `ws://` 주소에 붙지 못한다. 시뮬 단계는 같은 PC·현장 망의 HTTP 로 연다(NF-07 TLS 의 예외는 **시뮬·현장 망 시험에만**). 실기 전에 «로봇 인증서로 wss / 설치형 앱 / 로봇이 앱을 직접 내려줌» 중 하나를 정한다(§10).

### 5.1 조종권 — 로봇 안 하나의 판정
- 로봇마다 에이전트 안에 **조종권 판정기 하나, Session 하나, 명령 출력 하나**만 둔다. 폰마다 Session 을 만들지 않는다. 모든 취득·넘김·반납·끊김·실행(RUN) 전환은 이 판정기 한 곳에서 차례로(직렬) 처리한다. 동시에 온 두 취득 중 하나만 이긴다.
- 조종권(lease)은 **사용자 + 기기 + 이 WS 연결**에 묶인다. 같은 출입증·lease 를 다른 연결이 쓰면 거부한다. 연결이 바뀌면(재접속 포함) 옛 lease 는 끝나고 새로 취득한다.
- 바뀔 때 순서는 지금과 같다: 옛 입력 차단 → 0 + 잠금 적용 확인 → 새 lease → 조종자의 명시 해제 → 새 중립 입력 뒤에만 움직임. 정지 확인 실패(지금 `stop_ref` 2 s 규칙)는 넘김 실패로 다룬다.
- **관제 서버는 조종권을 발급하거나 덮어쓰지 않는다.** 서버 ↔ 에이전트 연결의 재접속·상태 동기화가 lease 를 바꾸지 못한다. 서버가 보내던 `lease`·`cmd`·`unlock` 은 받지 않는다.
- 조종권 요청·넘김의 사람 규칙(SF-05~07: 먼저 잡은 사람 우선, 요청 → 넘기기/거절, 10 s 자동 거절)은 그대로 두고 판정 위치만 에이전트로 옮긴다. 조종자 연결이 끊기면 0.3 s 에 0, 마지막 연결 확인 15 s 뒤 조종권을 비운다(SF-08 과 같은 값).
- 에이전트가 다시 시작하면 조종권은 비어 있고 잠금 상태로 시작한다(지금 «서버 재시작 → 잠금»과 같은 뜻, 06 §3.7 의 «서버 메모리»는 «에이전트 메모리»로 바뀐다). `lease_log` 는 에이전트가 보낸 기록으로 서버에 쌓는다.

### 5.2 출입증 — 서버 없이 확인하되 오래 남지 않게
- 담는 것: 조직·사용자·대상 로봇 하나·기기 ID·용도(조종 / 보기만)·발급·만료 시각·고유 ID. 에이전트는 서명·로봇·용도·만료를 모두 확인한다.
- **수명 상한 10 분**(제안 값, 계약에서 확정). 받을 때 믿을 수 있는 UTC 로 남은 수명을 확인하고, 그 **남은 시간만** 에이전트 단조 시계 마감으로 고정한다. 재접속·에이전트 재시작이 수명을 다시 10 분으로 늘리지 않는다. 열린 연결 중 시계 신뢰가 깨지면 0 + 잠금 후 비운다. 폰은 서버에 닿을 때 만료 전 새 출입증으로 갱신한다. 열린 연결에서 출입증이 만료되면 그 조종권은 0 + 잠금 후 비운다.
- 한 출입증은 한 번에 한 연결만. 같은 고유 ID 로 두 번째 연결이 오면 거부한다.
- 에이전트 시계가 믿을 수 없으면(동기화 안 됨 표시·역행) 출입증을 받지 않는다.
- **권한 회수 한계:** 계정 잠금·담당 해제·강제 로그아웃은 서버에 닿는 순간 에이전트에 «회수 목록»으로 보낸다. 서버와 끊긴 현장에서는 **최대 출입증 수명(10 분)까지** 권한이 남을 수 있다. 이것이 AU-04·05 §1.2 의 «매 메시지 서버 재확인»을 바꾸는 범위다.

### 5.3 정지 요청 (총괄 웹)
- 받는 사람 = 그 로봇의 **지금 조종자**(없으면 등록 담당자). 넘김 중이면 둘 다.
- 상태를 나눠 보인다: 접수(서버) → 폰 받음 → 사람 확인 → 로봇 STOP 적용(에이전트 보고) / 확인 안 됨. «폰 받음»을 «멈춤»으로 표시하지 않는다. 요청마다 ID, 같은 ID 는 한 번만.
- 폰이 없거나 끊긴 로봇은 §7 규칙으로 이미 멈춰 있어야 한다. 정지 요청은 그 위의 사람 알림이다.

## 6. 시뮬

- **한 월드에 여러 로봇.** 두 사람이 시뮬을 쓰면 같은 월드에 로봇이 한 대씩 더 생긴다(1인 1대, 실제 현장과 같다). 사람마다 월드를 따로 띄우지 않는다(이 PC 메모리 여유가 작다). 로봇마다 ROS 이름 공간·TF·명령 출력·포트를 따로 두고 서로 섞이지 않는지 시험한다.
- 시뮬 로봇마다 자기 에이전트(연결 서버)를 가진다. 폰은 실기와 똑같이 그 에이전트에 붙는다.
- **시뮬 관리자:** 시뮬 PC 에서 도는 작은 서비스가 «월드 띄우기 / 로봇 넣기 / 로봇 빼기 / 목록»을 한다. 폰은 관제 서버를 거쳐 요청하고, 연결할 에이전트 주소를 받는다.
- 지도 = 월드 파일 + 지도 파일 짝. 지도 만들기는 시뮬 안에서 SLAM 으로 한다.
- 새 시뮬은 운영 시뮬과 다른 ROS 도메인(93)·포트에서만 띄운다. 운영 중인 시뮬·앱 포트는 건드리지 않는다. 첫 기동은 제품 책임자 승인 뒤(08 §6).
- **모든 감시는 시뮬 시간이 아니라 에이전트의 단조 벽시계로 잰다.** deadman 0.3 s, 폰 연결 감시, sink 감시, 출입증 만료 모두. 시뮬이 느려지거나 멈춰도 마감은 늘지 않는다. 시뮬 시계와 벽시계 차이는 상태에 싣고 화면에 보인다(참고용).
- 시뮬 센서(배터리 등)의 대체값은 «시뮬» 출처를 붙여 보내고 실측처럼 보이지 않게 한다.
- 화면에는 항상 «시뮬» 표시를 둔다.

## 7. 안전

바뀌지 않는 것:
- STOP: 0 명령 + 목표 취소 + 잠금. 사람이 풀 때까지 아무것도 재개하지 않는다. 그 로봇에 붙은 폰은 보기만 상태여도 누구나 STOP 을 누를 수 있다(SF-01).
- deadman 0.3 s: 폰 입력이 끊기면 로봇이 스스로 0.
- 안전 Core 판정·상수·셀프테스트 기대값은 바꾸지 않는다. 에이전트가 폰 WS 를 받는 부분은 08 §3 «안전 범위»(두 모델 검토)다.

새 규칙 — **폰 없는 자율 실행 금지:**
- 시나리오·목표 이동(RUN)은 **그 로봇 조종자 폰의 현장 연결이 살아 있는 동안만** 움직인다. 지금은 RUN 중 deadman 이 실행기 입력만 보므로, 폰이 사라져도 계속 갈 수 있었다. 그 빈틈을 막는다.
- 조종자 폰 연결 확인이 끊기면(폰 연결 감시, 단조 시계 기준 — 값은 0단계 계약에서, 15 s 를 넘지 않게) 0 + 목표 취소 + 잠금, 실행은 «일시정지». 다시 붙은 뒤 사람이 «이어서»를 눌러야 움직인다. 관제 서버 연결이 살아 있어도 마찬가지다.
- **관문:** 이 규칙은 2단계(시나리오·목표) 시작 전에 제품 책임자가 확정한다. 확정 전에는 폰 없는 RUN 을 켜는 코드를 합치지 않는다.

## 8. 단계 — 시뮬 먼저, 실기 없이 끝까지

| 단계 | 먼저 있어야 하는 것 | 결과 | 통과 기준 |
|---|---|---|---|
| 0 | — | (작업명 P1-A) 폰 ↔ 에이전트 계약(§5.1·5.2), 에이전트 폰 연결 서버, 출입증 발급(서버), 화면 틀(§3·§4 배치) | 가짜 폰·가짜 sink 시험: 조종자 한 명·출입증·끊김 정지·deadman |
| 1 | 0 + 시뮬 관리자 + 카메라 원천 + 첫 기동 승인 | 폰 «시뮬 로봇 띄우기» → Gazebo 월드에 로봇 한 대 + 그 에이전트 → 조이스틱·STOP·카메라 | 격리 Gazebo 1대 시뮬 시험: 명령 지연 95 분위 ≤ 100 ms(같은 PC·현장 망), 입력 끊김 → 0 까지 ≤ 0.4 s, STOP 뒤 재개 없음, 출입증·조종자 규칙(실기 정지 거리 기준은 실기 단계) |
| 2 | 1 + §7 관문 확정 + 승인된 지도·배정 + Nav2 지원 경로 | 지도·목표 시트(Nav2) → 시나리오 시트(실행·개입·이어서) | 폰 끊김 → 일시정지·잠금, «할 수 없음» 표시 |
| 3 | 1 | 총괄 웹 «로봇» 목록·마지막 수신, 정지 요청(§5.3), 기록에 STOP·개입. 이때 PC 머리줄 STOP 을 뺀다 | 정지 요청 상태 단계가 화면에 맞게 |
| 4 | 1 | 두 번째 사람이 같은 월드에 로봇 한 대 더 → MuJoCo 교차 확인 | 두 로봇 명령·TF 섞임 0 |

- 2026-10-22 후속 결정: **시뮬 폰 조이스틱**은 전진0 또는0.2~1.0 m/s 연속, 전진 중에만 회전±0.5 rad/s 고정이며 놓으면 감속 없이 즉시 명령0이다. 후진·옆·제자리 회전은 차단한다. 실기는 기존0.6 전진의4개 명령, Nav2는 기존 제한을 유지한다. 시뮬 phone Session만 연속 투영을 사용하며 STOP·중립·deadman 등 Core 관문은 유지한다. 폰은 welcome.limits의 연속 구간을 읽고 에이전트가 최종 판정한다([측정·계약·한계](DRIVE-MODES-VALIDATION.md)). 측정 표본 사이와 vx/wz 조합 전체의 보행·안정 정지 보장을 뜻하지 않는다.
- 실기 연결(04 §6)은 이 단계들이 시뮬에서 통과한 뒤 같은 계약으로 붙인다.

**명령 주인** (05 §10.2 의 서버 → 에이전트 메시지)
| 메시지 | 새 주인 |
|---|---|
| `lease`·`cmd`·`unlock` | 서버가 보내지 않는다. 폰 ↔ 에이전트(§5.1) |
| `stop` | 폰 → 에이전트만. 서버는 로봇에 `stop` 을 보내지 않는다 — 정지 요청은 서버 → 폰 알림, STOP 은 사람이 폰에서, 적용 확인은 에이전트 → 서버 보고(§5.3). 에이전트는 옛 서버 `stop` 을 받으면 멈춤 쪽으로만 처리한다(방어용, 발신 경로 아님) |
| `run.start`·`run.control`·`run.confirm` | 폰이 에이전트로 보낸다. 실행 계획 자료는 서버가 승인된 배정에서 만들어 폰이 받아 넘기거나 서버가 미리 내려 둔다 — 2단계 계약에서 정한다 |
| `map.sync` | 서버 → 에이전트 유지(승인 판 자료 배포) |
| `floor.set` | 폰 → 에이전트, 조종자만 |
| `slam` start·save·cancel | 폰 → 에이전트 직결, 조종자만. 서버가 보내는 `slam` 은 거부. 저장한 지도는 에이전트가 서버로 올리고 승인 요청이 된다 |
| `streams` | 폰 ↔ 에이전트 |

그대로 쓰는 것: 계정·역할 자료, 임무·시나리오·배정(MS), 결재(AP), 기록(LG), 지도(MP)의 데이터 모델과 화면, 안전 Core, 디자인 토큰. 위 표의 권한·실행 의미 변경은 이것과 별개다.
