## 1. 메뉴 구조

### 1.1 PC
| 순서 | 탭 | 총괄 운영 관리자 | 운영 관리자 |
|---|---|---|---|
| 1 | 관제 | 전체 로봇 | 전체 로봇(내 로봇 먼저, 남의 로봇 보기 전용) |
| 2 | 조종 | 전체 로봇 조종 가능 | 내 로봇만 조종 가능 |
| 3 | 임무 | 임무·시나리오 편집, 배정 바로 확정 | 편집 가능, 배정은 결재 요청 |
| 4 | 결재 | **결재함** (처리) | **내 요청** (상태 보기·취소) |
| 5 | 기록 | 전체 | 내 로봇·내 행동 |
| 6 | 지도 | 편집 바로 반영(새 판) | 편집은 결재 요청 |
| 아래 | 설정 | 계정·로봇 배정·조직 설정 + 개인 설정 | 개인 설정 |

- 로봇 탭은 없앤다. 그 내용은 관제의 로봇 상세 서랍으로 간다. (확정)
- 메뉴에 없는 숨은 화면을 두지 않는다. 지금의 임무 양식(PcMissions)은 임무 탭, 사진 검토(PcReview)와 보고서(Report)는 기록 탭 안으로 들어간다. 디자인 견본(System)은 제품에서 뺀다.
- 결재 탭 배지: 총괄은 대기 건수, 운영 관리자는 "결과가 나왔지만 아직 안 본 요청" 건수.

### 1.2 폰 (운영 관리자)
| 순서 | 탭 | 내용 |
|---|---|---|
| 1 | 조종 | 내 로봇 영상 + 두 엄지 조종 |
| 2 | 시나리오 | 내 로봇에 배정된 시나리오 카드, 실행 |
| 3 | 기록 | 내 로봇 실행·사건 |

- 머리줄: 로봇 이름(여러 대면 눌러서 바꿈) · 연결 점 · STOP.
- 운영 관리자의 폰 로봇 고르기는 자기 담당 로봇만 보인다(PC 처럼 남의 로봇을 보기 전용으로 섞지 않음).
- 총괄이 폰으로 들어오면 "결재 · 알림" 2탭만 보인다. (P2, 제안)

### 1.3 기기 판별
- 화면 너비 기준(768 px 미만 = 폰 화면). UA 만으로 판별하지 않는다.
- 예외는 하나: 손가락 입력(`pointer: coarse`) + 가로 + 높이 480 px 이하면 눕힌 폰으로 보고 폰 틀을 쓴다. 마우스를 쓰는 낮은 창(예: 1440×400)은 PC 틀이다.
- 폰에서 PC 화면 보기 링크를 둔다(설정). 반대도 마찬가지.

## 2. 공통 기능

### F-COM-01 STOP (SF-01, SF-02)
- 모든 화면 오른쪽 위 같은 자리. 키보드 Space. 폰은 64 px 이상.
- Space 예외(10-20 결정): 초점이 글 입력칸(글자를 넣는 input·textarea·contenteditable, readonly·disabled 제외)에 있으면 Space 는 띄어쓰기이고 STOP 이 아니다. 그 밖(단추·체크박스·빈 곳·확인창·요청 창 포함)에서는 Space = STOP. 화면의 STOP 단추는 언제나 보이고 바로 눌린다.
- 대상: **지금 화면이 가리키는 로봇**. 관제 탭처럼 로봇이 정해지지 않은 화면에서는 STOP 이 "로봇 고르기" 펼침이 되고, 내가 조종 중인 로봇이 있으면 그 로봇이 기본이다.
- 누르면 서버에 정지 요청 → 로봇 에이전트가 0 명령 + 잠금. 화면은 "정지 요청됨" → 로봇이 확인하면 "정지 잠금".
- STOP 은 조종권이 없어도, 운영 관리자가 남의 로봇에도 누를 수 있다(보기 권한이 있으면). 누른 사람은 기록에 남는다.
- 잠금 해제: 조종권자만, "잠금 해제" 버튼으로. 해제 뒤에도 중립 입력이 한 번 들어와야 움직인다(기존 규칙 유지).

### F-COM-02 연결 상태 표시
- 정상: 머리줄 초록 점 하나.
- 문제: 화면 위 띠 한 줄. "무엇이 안 되는지 + 무엇을 하면 되는지". 예: "Go2-3 연결이 끊겼습니다. 마지막 확인: 정지 잠금(14:02:11). 지금 상태는 알 수 없습니다. [다시 연결]". 끊긴 동안의 로봇 상태는 단정하지 않고 «마지막 확인 상태 + 미확인»으로 쓴다.
- HTTP 코드·내부 이름은 개발자 모드에서만.

### F-COM-03 알림
- 종류: 결재 요청/결과, 조종권 요청, 실행 실패·완료, 연결 끊김, 배터리 부족(기본 20 %, 설정 가능), 경로 이탈, 긴급 실행 발생.
- PC: 머리줄 종 + 화면 오른쪽 아래 짧은 알림. 폰: 푸시 알림(PWA Web Push, 설치형 앱이면 기기 알림).
- 알림을 누르면 해당 화면·항목으로 바로 간다.

### F-COM-04 권한에 따른 단추 처리 (AU-04)
| 경우 | 화면 처리 |
|---|---|
| 권한 있음 | 보통 단추 |
| 결재가 필요함 | 같은 자리, 이름만 "승인 요청"으로 바뀜 |
| 권한 없음, 사용자가 찾을 만한 단추 | 자물쇠 + 누르면 이유 한 줄 ("담당자: 박OO") |
| 권한 없음, 찾을 일 없는 단추 | 숨김 |

### F-COM-05 개발자 모드
- 주소 `?dev=1` 또는 설정 스위치. 서버 원값·판 해시·내부 진단·HTTP 코드를 보여 준다. 운영 화면에서는 모두 숨긴다.

## 3. 관제 탭

### F-FL-01 요약 수치 (FL-01)
| 칸 | 계산 | 누르면 |
|---|---|---|
| 전체 로봇 | 조직(운영자는 전체) 로봇 수 | 목록 필터 해제 |
| 임무 중 | 끝나지 않은 실행(`PREPARING`/`MOVING`/`AT_WAYPOINT`/`PERFORMING`/`WAIT_CONFIRM`/`PAUSED`)이 있는 로봇 = 로봇 요약의 `current_run` 이 있는 로봇. 요약 `status`(잠금·오류·사람 조종)와 무관하게 센다. `QUEUED` 만 있으면 넣지 않는다 | 목록을 임무 중으로 필터 |
| 주의 필요 | 연결 끊김 + 배터리 부족 + 오류 + 정지 잠금 | 목록을 주의로 필터 |
| 결재 대기 | 총괄: 대기 건수 / 운영자: 내 대기 요청 | 결재 탭 |

- 운영 관리자 현황(계정 수, 운영자별 로봇 수)은 요약 아래 작은 막대 그래프. 총괄에게만 보인다.

### F-FL-02 로봇 목록 (FL-02)
- 열: 상태 점 · 이름 · 배터리 % · 현재 임무(시나리오 이름, 진행 n/m) · 층 · 담당자.
- 정렬: 주의 필요 → 임무 중 → 대기 → 끊김. 운영자는 내 로봇이 위.
- 남의 로봇 행에는 자물쇠 표시. 상세는 열리지만 조종·배정 단추는 자물쇠.

### F-FL-03 전체 지도 (FL-03)
- 장소·건물·층 고르기. 그 층의 로봇을 아이콘으로(방향 포함). 다른 층 로봇 수는 층 단추에 숫자로.
- 아이콘을 누르면 상세 서랍이 열린다(목록 행 누름과 같음).
- 실행 중 로봇은 계획 경로(점선)와 지나온 경로(실선)를 그린다.

### F-FL-04 로봇 상세 서랍 (FL-04, FL-05, FL-06, FL-08)
위에서 아래 순서:
1. 이름 · 상태 · 담당자 · [조종하기] [시나리오 배정] (권한에 따라 F-COM-04)
2. 위치: 작은 지도(층, 좌표, 마지막 갱신 시각)
3. 현재 임무: 시나리오 이름·판, 진행(지점 n/m, 현재 작업), 이탈 여부(정상 / "계획 경로에서 1.8 m 벗어남")
4. 상태: 배터리(%, 예상 남은 시간은 값이 오면), 부착 장치 목록(카메라·라이다·뎁스·기타: 연결/끊김), 통신 품질
5. 그래프(최근 30분, 고르면 2시간·오늘): 배터리, 속도, 통신 지연
6. 최근 사건 5개 + "기록에서 전체 보기"
7. 고급(접힘): 정지 계층, 원값, 펌웨어·에이전트 판

- [조종하기]: 조종 탭으로 이동, 그 로봇이 선택된 상태로 열림(조종권은 아직 잡지 않음).
- [시나리오 배정]: 배정 창(F-MS-05)을 그 로봇으로 연다.

### F-FL-05 경로 이탈 감지 (FL-07)
- 로봇 에이전트가 실행 중 "현재 위치 ↔ 계획 경로(Nav2 가 만든 경로)" 최소 거리를 1 Hz 로 계산한다.
- 기준(기본 1.5 m, 조직 설정) 이상이 5 s 넘게 이어지면 `ROUTE_DEVIATION` 사건. 기준 안으로 돌아오면 `ROUTE_RECOVERED`.
- 위치 확신도(localization 점수)가 낮으면 이탈 판정을 하지 않고 `LOCALIZATION_LOW` 사건을 낸다(잘못된 경고 방지).

## 4. 조종 탭

### F-TO-01 로봇 고르기 (TO-01)
- 탭에 그냥 들어오면 조종 가능한 로봇 카드 목록(상태·배터리·조종권자). [직접 조종] 을 누르면 그 로봇 조종 화면.
- 관제에서 [조종하기] 로 들어오면 바로 조종 화면.

### F-TO-02 조종 화면 (TO-02)
- 큰 칸: RGB 영상. 작은 칸(오른쪽 아래, 크게 보기 가능): 지도 + 로봇 위치 + 라이다 점(겹쳐 그림).
- 보기 전환 단추: [RGB] [뎁스] [지도 크게]. 뎁스는 색으로 거리 표현.
- 상태 한 줄: 조종권자 · 속도 · 지연(ms) · 배터리.
- 실행 중 시나리오가 있으면 진행 막대 + [일시정지] [중단].

### F-TO-03 조종 시작·끝
1. [조종 시작] → 조종권 잡기 요청.
2. 조종권이 비어 있으면 받음. 처음 잡을 때도 F-TO-04 «넘김 순서» 2단계와 같은 정지 확인을 지난 뒤 준다. 로봇은 잠금 상태로 시작.
3. [잠금 해제] → 중립 입력 확인 → 움직일 수 있음.
4. [조종 끝내기] → 0 명령 + 잠금 + 조종권 반납.
- 화면을 떠나거나 탭을 숨기면 자동으로 정지·잠금·반납(기존 규칙 유지).
- 자율 실행 중에 [조종 시작] 하면 "시나리오가 일시정지됩니다" 확인 뒤 일시정지 + 조종권 받음(SF-10).

### F-TO-04 조종권 요청 (SF-05~SF-08) — 확정 + 제안 보완

**흐름**
```
요청자 B                      서버                         조종권자 A
[조종 시작] ───────────────▶ 조종권 있음(A) 확인
                              요청 생성(10 s 유효)  ─────▶ 창: "B(총괄 김OO)님이 조종권을
"A님에게 요청했습니다…"                                     요청했습니다. 넘겨주시겠습니까?"
 (10 s 남은 시간)                                          [넘기기] [계속 조종]  (10 s 막대)
                              ◀───────────────────────── 넘기기
                              로봇 0 명령 + 잠금 확인
                              조종권 A → B
"조종권을 받았습니다.         ─────────────────────────▶ "조종권을 넘겼습니다. 보기 전용"
 잠금 해제 후 조종하세요"
```

**규칙**
| # | 규칙 | 이유 |
|---|---|---|
| 1 | 먼저 조종하던 사람이 우선. 요청자는 요청만 보낸다 | 확정 |
| 2 | 응답 없으면 10 s 뒤 **자동 거절** (계속 조종) | 운전 중 사람이 못 본 사이에 조종이 넘어가면 위험 |
| 3 | [넘기기] → 아래 «넘김 순서»로 로봇의 0 명령·잠금을 확인한 뒤 넘긴다. 새 조종권자는 잠금 상태에서 시작 | 넘기는 순간의 입력 충돌 방지 |
| 4 | 요청 창의 단추는 마우스·터치로만 누른다. Enter·Space 가 단추를 누르지 않는다. Space 는 계속 STOP(글 입력칸 초점 중 제외 — F-COM-01), 방향키는 계속 조종 | 운전 중 키 입력이 실수로 "넘기기"를 누르는 사고 방지 |
| 5 | 한 로봇에 대기 중인 요청은 1건. 거절된 같은 요청자는 30 s 뒤 다시 요청 가능 | 창 폭탄 방지 |
| 6 | 조종권자 연결이 끊기면 로봇은 0.3 s 뒤 deadman 으로 0 명령·입력 폐기(잠금은 아님, PRD Q7). 조종권은 마지막 유효 heartbeat 15 s 뒤 비워지고 요청자에게 "조종권이 비었습니다" | 무응답 대비 |
| 7 | 거절·넘김·자동 거절 모두 기록(누가, 언제, 어느 로봇) | 감사 |
| 8 | 강제 회수는 두지 않는다. 급하면 누구나 STOP | PRD Q3 제안 |

**시간 기준 (한곳 정본)**
| 시간 | 값 | 기준 시각 | 끝나면 |
|---|---|---|---|
| 요청 응답 | 10 s (조직 설정 `lease_request_timeout_s`) | 서버가 요청을 만든 때 | 자동 거절(`TIMEOUT`), 기존 조종 유지 |
| 같은 요청자 재요청 제한 | 30 s | 거절·자동 거절이 확정된 때 (`TIMEOUT` 포함) | 다시 요청 가능. 제한 중 요청은 429 `LEASE_REQUEST_COOLDOWN`. 서버가 재시작하면 제한은 사라진다(조종권도 함께 비워짐) |
| 조종권자 heartbeat | 15 s | 마지막 유효 명령(0 포함)을 받은 때 | 조종권 비움(`EXPIRE`) |
| deadman | 0.3 s | 에이전트가 마지막 cmd 를 받은 때 | 0 명령 + 입력 폐기 (SF-03) |

**넘김 순서** (규칙 3)
1. 서버가 A 의 입력을 막는다: 에이전트에 `lease {lease_id:null}` 를 보낸다. 에이전트는 받는 즉시 0 명령 + 입력 폐기를 하고, 새 lease 와 새 중립 입력 전까지 0 이 아닌 명령을 내지 않는다(아래 2단계가 안 와도 이미 0).
2. 서버가 로봇별로 1 씩 늘린 `stop_ref` 를 실은 `stop` 을 보내고, 2 s 안에 에이전트 `state` 에서 **같은 `stop_ref`** + `latched=true` + `applied=[0,0,0]` 을 확인한다. 에이전트는 그 STOP 을 적용한 뒤 마지막으로 적용한 `stop_ref` 를 `state` 에 되돌린다. 따로 ACK 는 없고, `stop_gen` 증가로 추정하지 않는다([05 §10.5](05-API-SPEC.md#105-정지-확인-stop_ref)).
3. 확인되면 B 에게 새 `lease_id` 를 발급한다. B 는 잠금 상태에서 시작.
4. 2 s 안에 확인이 안 되면(늦은 확인·다른 `stop_ref` 포함) 넘김 실패: 조종권은 아무에게도 주지 않고(비움, `FREE`), 로봇은 STOP 요청 상태로 두며, A·B 에게 "로봇 정지 확인 실패"를 알린다(`lease.result` = `CANCELED` + `STOP_CONFIRM_FAILED`).
- 여기서 확인하는 것은 **그 STOP 을 적용한 0 명령·잠금**이다. 몸이 실제로 섰는지(속도 0)는 따로 판정하지 않는다.

**문구**
- 조종권자 창 제목: "조종권 요청"
- 본문: "{역할} {이름}님이 {로봇} 조종권을 요청했습니다. 넘겨주시겠습니까?"
- 단추: [넘기기] [계속 조종] — "거절"보다 "계속 조종"이 지금 상태를 유지한다는 뜻이 분명하다.
- 요청자: "{이름}님에게 요청했습니다. ({n}초)" → "거절했습니다" / "응답이 없어 요청이 끝났습니다"

### F-TO-05 키보드·마우스 (TO-03)
| 입력 | 동작 |
|---|---|
| W / ↑ | 전진(키보드 기본 0.6 m/s). 시뮬 폰 조이스틱은 0.2~1.0 m/s 연속 구간 사용 |
| S / ↓ | 후진 차단·"후진은 아직 지원하지 않습니다" 표시. 저속 후진 결정은 후속 보행 확인 전까지 보류 |
| A / ← , D / → | 전진과 함께 왼쪽/오른쪽 ±0.5 rad/s 고정 회전. 회전 단독 입력은 차단 |
| Space | STOP (글 입력칸 초점 중에는 띄어쓰기 — F-COM-01) |
| 마우스 | 영상 위 화면 막대: 누르고 있는 동안만 움직임, 놓으면 감속 없이 즉시 명령0 |
- 동시 입력은 두 곳까지(기존 규칙). 입력은 50 ms 마다 보내고, 0.3 s 끊기면 로봇이 멈춘다.
- 실제로 나가는 속도는 에이전트가 최종 판정한다. 시뮬 폰 전진은 0 또는 [0.2, 1.0] m/s 연속이다. 0 초과 0.2 미만은 이유와 함께0, 1.0 초과는1.0으로 자른다. vy·후진·제자리 회전은0이며 전진할 때만 wz 문턱 ±0.5에서 고정 ±0.5로 투영한다.
- 실기는 기존 정지·전진0.6·전진0.6/회전±0.5의 4개 명령을 유지한다. 시뮬 welcome.limits의 `vx_mode=continuous`, `vx_min_moving=0.2`, `vx_max=1.0`을 폰이 읽는다. `commands=[]`는 연속 모드이며, 모드가 없으면 기존 `commands` 이산 목록을 사용한다. [측정·정지 한계](DRIVE-MODES-VALIDATION.md)를 따른다. 조이스틱 화면 반영은 후속 작업이다.

## 5. 임무 탭

### 5.1 개념
| 이름 | 뜻 | 예 |
|---|---|---|
| 작업 | 로봇이 한 지점에서 하는 한 동작 | 사진 찍기, 30 s 대기, 운영자 확인 받기, 센서 값 기록 |
| 임무 | 작업 묶음. 재사용한다 | "계기판 점검" = 사진 → 운영자 확인 |
| 시나리오 | 지도(여러 층 가능) 위 지점 순서 + 지점마다 임무 | "2층 순찰" = A(계기판 점검) → B(사진) → C(대기) |
| 배정 | 시나리오 판을 로봇에 연결 | "2층 순찰 v3 → Go2-3" |
| 실행 | 배정의 한 번 실행 기록 | "2026-10-20 09:12 실행, 완료" |

### F-MS-01 임무 편집 (MS-01, MS-09)
- 목록 → [새 임무] → 이름 → 작업 추가(드래그로 순서) → 저장.
- 작업 목록은 서버의 "작업 카탈로그"에서 온다. 로봇의 부착 장치로 할 수 없는 작업은 회색 + 이유.
- 저장할 때마다 새 판. 이미 배정된 판은 바뀌지 않는다.

### F-MS-02 시나리오 편집 (MS-02, MS-03)
화면 하나에서 끝낸다(지금의 6단계를 3단계로):
1. **지도**: 장소·건물·층 고르기(지도 승인 판만).
2. **지점**: 지도를 눌러 지점 추가(이미 이름 붙은 지점도 고를 수 있음), 순서 끌어서 바꾸기, 층 바꿔 이어서 찍기 가능. 지점마다 임무 고르기.
3. **확인·저장**: 경로 미리보기(층 연결점 경유 표시), 예상 거리, 필요한 장치 목록. [저장] → 새 판.
- 종료 방식: 마지막 지점에서 대기 / 시작 지점으로 복귀 / 지정 지점으로 이동.

### F-MS-03 경로 미리보기
- 서버가 "지도 판 + 지점 순서"로 층 간 경로를 계산해 보여 준다(층 내부 경로는 실행 때 Nav2 가 다시 계산).
- 갈 수 없는 지점(진입 금지 구역 안, 층 연결점 없음)은 빨간 표시 + 저장 막음.

### F-MS-04 시나리오 목록
- 열: 이름 · 지도 · 판 · 지점 수 · 배정된 로봇 · 마지막 실행 결과.
- 필터: 내 것 / 전체, 지도별.

### F-MS-05 배정 (MS-04, AP)
- 시나리오 상세 또는 관제 서랍에서 [배정] → 로봇 고르기(권한 안의 로봇만) → 메모.
- 총괄: 바로 `ACTIVE`. 운영 관리자: 결재 요청(`PENDING`) → 승인되면 `ACTIVE`.
- 한 로봇에 여러 시나리오가 배정될 수 있다(폰 카드 여러 장).
- 배정 해제는 결재 없이 가능(안전을 줄이지 않음). 기록은 남는다.

### F-MS-06 실행 (MS-05, MS-06, MS-07, MS-08)

**실행 전 점검 (SF-12)** — 모두 통과해야 [시작] 이 켜진다.
| 항목 | 통과 조건 |
|---|---|
| 배정 | `ACTIVE` (또는 긴급 실행 이유 입력) |
| 연결 | 로봇 연결 정상 |
| 배터리 | 기준 이상 (기본 30 %, 조직 설정) |
| 위치 | 위치 확신도 기준 이상. 층을 모르면 "지금 몇 층입니까?" 입력 요구 |
| 조종권 | 다른 사람이 조종 중이 아님 |
| 정지 잠금 | 풀려 있음 (잠겨 있으면 해제 안내) |
| 지도 판 | 시나리오의 지도 판이 현재 승인 판과 같음. 다르면 "지도가 바뀌었습니다. 시나리오를 확인하세요" |
| 장치 | 필요한 장치가 모두 연결 |

**실행 단계**
```
대기 ─▶ 시작 지점으로 이동(필요하면 층 이동) ─▶ 지점 1 도착 ─▶ 임무 수행 ─▶ 지점 2 … ─▶ 종료 방식 ─▶ 완료
          │                                          │
          └─ 일시정지 / 중단 / 수동 조종 개입 ────────┘
```
- 상태: `QUEUED → PREPARING → MOVING → AT_WAYPOINT → PERFORMING → … → COMPLETED / FAILED / ABORTED`, 아무 때나 `PAUSED` 가능. 층 전환·`OPERATOR_CONFIRM` 처럼 사람 확인을 기다리는 동안은 `WAIT_CONFIRM`.

<a id="로봇-요약-상태와-실행-상태"></a>**로봇 요약 상태와 실행 상태** — 요약 `status` 는 로봇 한 대의 주의·안전 표시용이다(위에서부터 먼저 맞는 것). «임무 중» 집계는 이것이 아니라 `current_run` 으로 센다(F-FL-01).
| 로봇 요약 `status` | 조건 |
|---|---|
| `STOP_LATCHED` | 에이전트가 잠금 상태 |
| `ERROR` | 에이전트가 오류 보고 |
| `TELEOP` | 사람이 조종권을 가짐 (진행 중 실행이 있으면 그 실행은 `PAUSED`) |
| `PAUSED` | 진행 중 실행이 `PAUSED` |
| `RUNNING` | 진행 중 실행이 `PREPARING`/`MOVING`/`AT_WAYPOINT`/`PERFORMING`/`WAIT_CONFIRM` |
| `IDLE` | 그 밖 (`QUEUED` 만 있는 경우 포함) |
- 연결이 끊긴 로봇은 `connection: OFFLINE` 이고 `status` 는 마지막 확인 값이다(화면은 "마지막 확인"으로 표시).
- 실패 이유 코드(예): `NAV_GOAL_REJECTED`, `NAV_TIMEOUT`, `LOCALIZATION_LOST`, `FLOOR_TRANSITION_FAILED`, `BATTERY_LOW`, `LINK_LOST`, `OPERATOR_ABORT`, `DEVICE_MISSING`, `STOPPED_BY_USER`.
- 지점 도착 판정: 목표 반경 0.5 m 이내 + 정지(제안).

### F-MS-07 다른 층 시작 (MS-06) — 확정 요구
- 로봇의 현재 층 ≠ 시나리오 시작 지점 층이면, 서버가 층 연결점 그래프로 경로를 만든다.
- 순서: 현재 층에서 연결점(계단 아래)까지 Nav2 이동 → **층 전환 구간** → 목표 층 지도로 바꾸고 연결점 짝 위치에서 위치 잡기 → 시작 지점까지 Nav2 이동.
- 층 전환 구간 처리(단계별, 제안):
  - **R3 첫 판**: 연결점 도착 시 "계단 구간입니다. 수동 조종 또는 계단 모드로 올라가세요" 알림 → 운영자가 통과 → 운영자가 "도착(n층)" 확인 → 자동 재개.
  - **다음 판**: 계단 보행 모드 자동 실행(로봇·정책이 지원할 때만).
- 현재 층 판단: 기본은 사람이 입력(실행 전 점검 / 층 전환 확인). 자동 판별(지도 맞춤 점수, 기압계 등)은 후속이며, 자동 판별 결과도 확신도가 낮으면 사람에게 묻는다.

### F-MS-08 긴급 실행 (AP-05) — 확정
- 실행 전 점검에서 "배정 미승인"만 실패한 경우에만 [긴급 실행] 이 보인다(안전 점검 실패는 긴급으로도 못 넘김).
- 이유 입력(10자 이상) → 실행. 총괄 전원에게 즉시 알림. 결재 탭에 `POST_REVIEW` 항목.
- 총괄이 사후 확인에서 "부적절"로 표시하면 기록에 남고 요청자에게 알림(실행 결과는 바꾸지 않음).

### F-AP-02 결재함 (총괄)
- 목록: 종류 · 요청자 · 대상(로봇/지도) · 요청 시각 · 긴급 표시. 기본 정렬: 사후 확인 → 오래된 것 먼저.
- 상세(오른쪽 칸):
  - 지도: 전후 비교(겹쳐 보기 / 나란히 보기 토글, 바뀐 곳 강조), 바뀐 항목 목록, 이유.
  - 배정: 시나리오 미리보기(지도·지점·임무), 대상 로봇 상태, 메모.
- [승인] [반려] — 반려는 이유 필수. 처리 뒤 다음 항목으로 자동 이동.
- 승인할 때 대상이 바뀌었으면(예: 같은 지도에 다른 판이 먼저 승인됨) 승인 막고 "요청 이후 지도가 바뀌었습니다" 표시. 요청자가 다시 요청해야 한다.

### F-AP-03 내 요청 (운영 관리자)
- 같은 탭, 같은 틀. 목록 상태: 대기 · 승인 · 반려 · 취소. 대기 중이면 [요청 취소].
- 반려 이유가 보이고 [고쳐서 다시 요청] 으로 편집 화면이 열린다.

### F-AP-04 결재 상태
```
DRAFT ─▶ PENDING ─▶ APPROVED
            │  └──▶ REJECTED
            └─────▶ CANCELED (요청자)

POST_REVIEW: OPEN ─▶ ACKNOWLEDGED / FLAGGED
```

## 7. 기록 탭

### F-LG-01 사건 목록 (LG-01, LG-02, LG-05, LG-06)
- 한 줄 = 한 사건 문장. 앞에 분류 아이콘·심각도 색. 시간 역순.
- 분류 필터 칩: 전체 · 임무 · 이탈 · 연결 · 조종권 · 결재 · 안전 · 계정.
- 행을 펼치면: 관련 로봇·사람·실행 링크, 원자료(개발자 모드).

### F-LG-02 문장 틀 예
| 사건 코드 | 문장 틀 |
|---|---|
| `RUN_COMPLETED` | "{시각} {로봇}이(가) '{시나리오}'를 마쳤습니다. 지점 {n}곳, {분}분." |
| `RUN_FAILED` | "{시각} {로봇}의 '{시나리오}'가 지점 {k}에서 실패했습니다. 이유: {이유 문장}." |
| `ROUTE_DEVIATION` | "{시각} {로봇}이(가) 계획 경로에서 {거리} m 벗어났습니다." |
| `LINK_LOST` | "{시각} {로봇}과(와) 연결이 끊겼습니다. 마지막 확인 상태: {상태}. 이후 상태는 확인되지 않았습니다." |
| `OPERATOR_DISCONNECTED` | "{시각} {사람}의 연결이 끊겨 {로봇} 조종권이 비워졌습니다." |
| `LEASE_HANDOVER` | "{시각} {A}님이 {로봇} 조종권을 {B}님에게 넘겼습니다." |
| `STOP_PRESSED` | "{시각} {사람}님이 {로봇} STOP 을 눌렀습니다." |
| `APPROVAL_DECIDED` | "{시각} {총괄}님이 {요청자}님의 {종류} 요청을 {승인/반려}했습니다." |
| `EMERGENCY_RUN` | "{시각} {사람}님이 결재 없이 '{시나리오}'를 긴급 실행했습니다. 이유: {이유}." |
- 조사(이/가, 과/와)는 앞말 받침에 맞춰 고른다.
- 문장은 사건을 저장할 때 만들고 코드·값과 함께 저장한다([06](06-DB-DESIGN.md) `events.message`).

### F-LG-03 실행 기록 (LG-03)
- 실행 목록: 시나리오 · 로봇 · 시작·끝 · 결과 · **실패 이유 한 줄**.
- 행 → 실행 상세: 지점별 결과(도착 시각, 작업 결과, 사진), 지도 위 계획/실제 경로, 그 시간대 사건 타임라인(이탈·끊김·STOP·조종 개입).
- [보고서] → 인쇄용 한 장(PDF 저장).

### F-LG-04 사진
- 실행 상세 안에서 지점별 사진. 분류(확인·보류·제외)와 메모는 선택 기능(P1, 지금 PcReview 기능 이식).

### F-LG-05 내보내기 (LG-04)
- 지금 필터 그대로 CSV 하나. 실행 보고서는 PDF.

## 8. 지도 탭

### F-MP-01 지도 목록 (MP-01)
- 왼쪽: 장소 → 건물 → 층 나무. 층마다 승인 판 번호, 대기 중인 수정 요청 표시.
- 가운데: 지도 보기(2D 기본, 3D 는 있으면). 오른쪽: 층 정보(판, 만든 사람, 날짜, 연결점 수).

### F-MP-02 새 지도 만들기 (MP-02)
- [새 지도] → 로봇 고르기(내 로봇) → 층 지정(사람 입력) → SLAM 시작 → 로봇을 조종해 돌기 → [저장] → 판 1 생성.
- 운영 관리자가 만든 새 지도도 승인 전에는 시나리오에 쓸 수 없다(`MAP_REVISION` 결재).

### F-MP-03 편집 (MP-03, MP-05, MP-06)
- 상단 토글 [보기 | 편집]. 편집 도구: 지우개(잘못 찍힌 장애물), 벽 그리기, 진입 금지 구역, 감속 구역, 지점(이름), 층 연결점.
- 층 연결점: 아래층 지점과 위층 지점을 짝으로 만든다(종류: 계단 / 엘리베이터(향후)). 짝의 두 지점 위치는 위치 잡기의 기준이 된다.
- [저장] → 총괄: 새 판 바로 승인. 운영 관리자: "무엇을 바꿨는지" 자동 목록 + 이유 입력 → 결재 요청.
- 편집 중 다른 사람의 승인으로 기준 판이 바뀌면 저장 때 알려 주고 새 판 위에 다시 적용할지 묻는다.

### F-MP-04 판 관리 (MP-04, AP-08)
- 판 목록, 두 판 비교, 이전 판으로 되돌리기(운영자는 결재).
- 실행 중인 로봇은 시작할 때의 판을 끝까지 쓴다. 새 승인 판은 로봇 에이전트에 미리 내려 두고 다음 실행부터 쓴다.

## 9. 설정

### F-ST-01 개인 설정 (모두)
- 테마(밝음/어두움/시스템), 조종 막대 배치(왼손/오른손), 알림 받을 종류, 개발자 모드, 비밀번호 변경.

### F-ST-02 조직 설정 (총괄)
- 계정: 만들기·잠그기·지우기·비밀번호 초기화·로그인 기기 보기/끊기.
- 로봇: 등록(등록 코드), 이름, 담당 운영 관리자 배정, 해제.
- 기준값: 배터리 부족 %, 실행 시작 최소 배터리 %, 이탈 거리 m, 조종권 요청 응답 시간(기본 10 s).
- 지원 범위 표: 로봇·장치별로 되는 것/안 되는 것과 이유.

## 11. 예외 처리 요약
| 상황 | 동작 |
|---|---|
| 조종 중 로봇 연결 끊김 | 로봇: 0.3 s 뒤 0 명령 + 입력 폐기(deadman, 잠금 아님 — PRD Q7). 다시 움직이려면 새 중립 입력. 화면: 띠(마지막 확인 상태 + 미확인) + 영상 멈춤 표시. STOP 잠금이었다면 재연결 뒤에도 유지 |
| 조종 중 내 화면 연결 끊김 | 같음. 15 s 뒤 조종권 비워짐 |
| 자율 실행 중 서버 연결 끊김 | 로봇: 끊긴 때(마지막 서버 신호 수신 시각, [04 §3.2](04-ARCHITECTURE.md#32-연결-끊김-처리))부터 `link_loss_wait_s`(조직 설정, 기본·상한 30 s) 안에 다음 지점에 닿으면 그 앞에서 대기, 시간이 먼저 지나면 그 자리에서 정지·잠금(PRD Q5 제안). 사건은 로봇이 쌓아 두었다가 재연결 때 올림 |
| 실행 중 배터리 기준 아래 | 경고 사건 + 알림. 자동 귀환은 하지 않음(도크 없음). 일시정지 여부는 조직 설정 |
| 실행 중 위치 확신도 낮음 | 일시정지 + 알림 "위치를 잃었습니다" |
| 결재 대상이 먼저 바뀜 | 승인 막고 `STALE` |
| 두 사람이 같은 시나리오 동시 편집 | 판 충돌 409 → "다른 사람이 먼저 저장했습니다. 차이 보기 / 내 것으로 새 판" |
