# ADR-001 — 웹·앱 재구축 방식: 고쳐 쓰기 vs 새로 만들기

| 항목 | 내용 |
|---|---|
| 문서 번호 | FH-SPEC-07 (ADR-001) |
| 상태 | **채택** (2026-10-19 제품 책임자 결정) |
| 작성일 | 2026-10-19 |
| 관련 | [01 PRD](01-PRD.md) · [03 화면·UX](03-UX-SPEC.md) · [04 아키텍처](04-ARCHITECTURE.md) |

## 1. 결정 (요약)

**화면과 서버는 새로 만든다. 디자인과 안전 로직은 옮겨 온다. 지금 앱은 새 앱이 안전 시험을 통과할 때까지 지우지 않고 그대로 둔다.**

"전면 수정"(지금 코드 위에서 고치기)도 아니고 "다 지우고 처음부터"도 아니다. 새 골격을 세우고, 검증된 부품만 골라 옮기는 방식이다.

## 2. 판단 근거 (2026-10-19 코드 확인)

### 2.1 지금 코드
| 영역 | 규모 | 상태 |
|---|---|---|
| 화면 `ui/src` | 17,255줄 | 화면 19개가 시안 HTML(`web/*.dc.html`)에서 **한 번 자동 생성한 뒤 손으로 고친** `.view.tsx` (머리 주석 "재생성 금지"). 큰 것: Main 992줄, Report 870, PcSettings 833 |
| 메뉴 | — | 10곳에 따로 하드코딩 |
| 로봇 모델 | — | 1대 전제(`LiveN = 0|1`, 로봇 바꾸면 새로 고침) |
| 서버 `sim/v2_link.py` | 3,358줄 | 로봇 1대 = 프로세스 1개, 인증 없음, **안전 판단 Core 가 여기 있음**(셀프테스트 10개·assert 약 443개) |
| 서버 `sim/v2_gate.py` | 743줄(미커밋 작업 사본 관측, 이 저장소 HEAD 는 514줄) | 로그인·권한. 계정은 파일, 세션은 메모리 |
| 저장 `server/` | 1,833줄 | SQLite 저장소·판 충돌(runcas)·리허설. 백엔드 시험 98개 |
| 계약 `contracts/v1` | 1,135줄 | Pydantic → TS 생성 |
| 화면 시험 | 59개 파일, 약 568개 | |

### 2.2 새 기획이 바꾸는 것
| 바뀌는 것 | 지금 코드에 미치는 영향 |
|---|---|
| 메뉴 7+숨은 6 → 6탭, 폰 두 벌 → 3탭 | 모든 화면의 틀과 이동이 바뀜 |
| 1대 → 여러 대 동시 | 상태 저장 구조(link·auth·status)의 전제가 바뀜 |
| 역할·결재 | 지금 없는 개념. 서버·DB 새로 필요 |
| 수동 기록 임무 → 자율 실행 | 임무 데이터·실행 흐름이 바뀜 |
| 로봇이 서버와 다른 기기 | v2_link(127.0.0.1 전제)를 로봇 쪽 에이전트로 나눠야 함 |

### 2.3 세 가지 방식 비교
| 기준 | A. 지금 코드 고쳐 쓰기 | B. 다 지우고 처음부터 | **C. 새 골격 + 부품 이식 (채택)** |
|---|---|---|---|
| 화면 | 생성 후 손으로 고친 19개 파일을 하나씩 뜯어고침. 메뉴 10곳 | 디자인을 다시 맞춰야 함 | 새 화면 틀에 기존 CSS·토큰·부품을 그대로 씀 |
| 1대→여러 대 | 전제가 코드 곳곳에 퍼져 있어 숨은 버그 위험 | 처음부터 여러 대 | 처음부터 여러 대 |
| 안전 로직 | 유지됨 | **검증된 안전 로직·시험을 버림 (가장 큰 위험)** | Core 와 시험을 그대로 옮겨 같은 시험으로 확인 |
| 디자인 유지 | 유지 | 재현 비용 큼 | 토큰·CSS 파일 그대로 → 유지 |
| 운영 중 앱 | 고치는 동안 흔들림 | 새 앱 나올 때까지 공백 | 지금 앱은 그대로 운영, 새 앱 병행 |
| 예상 작업량 | 큼 (뜯는 비용 + 숨은 결합) | 큼 (안전·디자인 재검증) | 중간 |

A 를 버린 이유: 바뀌는 범위가 "화면 몇 개"가 아니라 **전제(1대·역할 없음·수동·같은 PC)** 라서, 고치는 비용이 새로 짓는 비용보다 크고 숨은 결합 위험이 남는다.
B 를 버린 이유: 안전 Core 와 수백 개 시험, 디자인 토큰은 **이미 검증된 자산**이다. 버리면 같은 검증을 다시 해야 한다.

## 3. 옮기는 것 / 새로 만드는 것 / 버리는 것

### 3.1 옮긴다 (시험과 함께)
| 대상 | 지금 위치 | 새 위치 |
|---|---|---|
| 브랜드 토큰·글꼴·로고 | `ui/public/brand/**`, `ui/src/brand.css`, `BrandLogo.tsx`, `theme.ts` | 새 웹 앱 그대로 |
| 화면 CSS·칩 | `ui/src/live.css`, `app/chip.tsx` | 새 웹 앱 (칩은 상태 표시 하나로 정리) |
| 안전 Core (deadman 0.3 s = 0 명령 + 입력 폐기·새 중립 필요, STOP 잠금·stop_gen CAS·중립 확인, 명령 단계화, 입력 검사) | `sim/v2_link.py` Core(약 84~265행) + 셀프테스트 | 로봇 에이전트 |
| Go2 어댑터 규칙 | 기존 control-app 의 Go2 어댑터 | 로봇 에이전트 (실기 R4) |
| 인증 방식 (scrypt, 쿠키 속성, WS 1회용 티켓, 속도 제한, 메시지마다 권한 재확인) | `sim/v2_gate.py`, `sim/app_auth.py`, 게이트 인증 모듈(이 저장소 밖 원본 — R0 전에 확보) | 관제 서버 |
| 계약 생성 방식 (Pydantic → JSON Schema → TS) | `contracts/v1`, `tools/generate_contracts.py` | 관제 서버 (모델은 새로) |
| 화면 순수 로직 | `data/geom.ts`, `maps.ts`, `plan2d`, `persistDraft.ts` | 새 웹 앱 (필요한 것만) |
| 판 충돌 규칙·부분 고유 색인 | `server/store.py`, `server/runcas.py` | PostgreSQL 설계([06](06-DB-DESIGN.md)) |
| 조종 입력 규칙 (50 ms 송신, 두 곳까지, 화면 숨김 → 정지) | `data/link.ts`, `app/drive.tsx` | 새 웹 앱 |

### 3.2 새로 만든다
웹 앱 화면 전부(6탭·폰 3탭), 관제 서버(FastAPI), PostgreSQL 스키마, 로봇 에이전트 골격(서버 접속·임무 실행기·원격측정), 조종권 중재기, 결재, 사건 문장 생성, 층 경로 계산.

### 3.3 가져가지 않는다
| 대상 | 이유 |
|---|---|
| `.view.tsx` 19개와 `web/*.dc.html` 변환 경로 | 새 틀에서는 CSS·부품만 쓰면 된다 |
| 리허설(`server/rehearsal.py`, `data/rehearsal.ts`) | 새 기획에 없음. 이미 화면에서 빠짐 |
| 디자인 견본(System), 가스·LEL·음성 자리표시 | 운영 화면에서 뺌 |
| `registry.json`·`accounts.json` 파일 저장 | DB 로 대체 |

## 4. 진행 순서
1. **준비**: 지금 작업 사본의 커밋 안 된 변경(멀티로봇 게이트·registry 등 30개 파일)을 작업자가 커밋해 보존한다. 지금 운영 중인 앱은 그대로 둔다.
2. **R0**: 새 저장소 폴더(예: `apps/web`, `apps/server`, `apps/agent`)에 골격. 안전 Core 와 시험을 에이전트로 옮기고 **같은 시험 통과**를 첫 관문으로.
3. **R0'** (병행): 시뮬 Go2 + 에이전트 + Nav2 단일 층 목표 이동 검증.
4. **R1~R3**: [01 PRD §7](01-PRD.md#7-출시-단계-제안) 순서.
5. **바꿔 끼우기**: 새 앱이 안전 시험 + 누름 수 목표를 통과하면 운영 주소를 새 앱으로 바꾸고, 지금 앱은 보관 브랜치로.

## 5. 위험
| 위험 | 대응 |
|---|---|
| 안전 Core 를 옮기며 동작이 달라짐 | 기존 셀프테스트를 고치지 않고 그대로 통과시키는 것을 관문으로 |
| 두 앱 병행 중 헷갈림 | 새 앱은 다른 포트·주소. 운영 주소는 하나 |
| Nav2 자율 이동이 안 됨 | R0' 결과로 PRD MS-05 범위 조정 |
