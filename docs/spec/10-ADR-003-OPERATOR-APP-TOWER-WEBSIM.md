## 1. 결정 (요약)

1. **앱은 운영 계정 전용, 총괄은 별도 페이지.** 지금 앱(폰·PC 웹)은 운영 관리자(`OPERATOR`)만 쓴다. 총괄(`ORG_ADMIN`)은 별도 웹 페이지 «총괄 페이지»에서 결재·배정·로봇 현황 등을 본다. 총괄 계정은 그 페이지용으로 남긴다. 총괄은 실기 조종을 하지 않는다. (확정)
2. **운영 계정이 PC 웹에서 볼 로봇 범위 = 내게 배정된 로봇만.** 총괄은 전체. (확정 10-25)
3. **시뮬은 폰만이 아니라 운영 앱 PC 웹에서도.** PC 웹에 «시뮬» 탭 하나를 둔다(새 창 아님). 거기서 시뮬 로봇 띄우기·보기·키보드 조종·시나리오 실행을 한다. **실기 조종은 폰만**(ADR-002 그대로). 웹 시뮬은 동선·배치를 짤 때 의사결정을 돕는 기능이다. 로봇 배치·로봇별 시나리오(동선 짜기)는 나중이며 총괄 페이지 쪽 후보다. (확정)
4. **시뮬을 띄울 때 지도·시나리오를 고른다.** 시뮬 지도는 **Gazebo 월드에서 자동 등록**한다. 월드마다 2D 지도(png + yaml)를 만들어 지도 탭에 층으로 올리고, 시나리오 좌표가 시뮬과 맞게 한다. 공장 도면형·다층 월드를 먼저 쓴다(월드는 조사 중). 시나리오 몇 개를 미리 만들어 둔다. SLAM 지도 만들기는 나중. (확정)
5. **실행 1단계 단위 = 시나리오**(여러 지점을 차례로). 지점별 임무는 처음엔 **표시·기록만** 하고 동작(사진 등)은 하지 않는다. (확정)
6. **ADR-002 §7 «폰 없는 자율 실행 금지» 관문 확정.** 실기 = 조종자 폰 연결 필수(끊기면 실행 멈춤). 시뮬 = **실행을 건 화면(웹 또는 폰)의 연결**이 그 역할을 대신한다(끊기면 멈춤). 판정은 서버·에이전트가 하고 화면이 하지 않는다. 시뮬인지 아닌지는 **에이전트의 simulation 설정으로만** 정한다. (확정)

## 2. 배경

- ADR-002(10-21)는 앱을 «폰 조종 앱»과 «총괄 웹»으로 나눴다. 총괄 웹은 메뉴(로봇·결재·시나리오·지도·기록·설정)를 총괄·운영이 같이 쓰고 권한만 달랐다(02 §1.1).
- 10-23 점검(지도·시나리오 탭, 총괄/운영 차이)에서 확인한 것:
  - PC 화면은 총괄·운영이 같은 틀이라 차이가 거의 안 느껴진다. 운영자 PC 로봇 목록도 전체가 보인다(02 §1.1 대로).
  - 폰에서는 총괄이 모든 로봇을 조종 후보로 본다(02 §1.2 «총괄 폰 = 결재·알림 2탭»과 다름).
  - 시나리오 편집·배정·결재는 되지만 **실행은 자리만** 있다(서버 실행 API·에이전트 실행기 연결 없음).
  - 시뮬 월드와 지도가 짝이 없다. 시나리오 좌표가 시뮬에서 의미가 없다.
  - 결정이 필요한 항목: 운영자 PC 범위, 총괄 폰, 지도 원천, 실행 단위(목표 점 / 시나리오), 웹 시뮬 여부.
- 제품 책임자 결정(10-23): 위 §1. «총괄은 실기 조종을 안 한다고 한 것이고, 시뮬은 동선이나 배치를 짤 때 의사결정을 돕기 위해 넣어 둔 기능»이라는 취지로 웹 시뮬을 연다.

## 3. 운영 앱과 총괄 페이지

| | 운영 앱 (폰) | 운영 앱 (PC 웹) | 총괄 페이지 |
|---|---|---|---|
| 계정 | 운영 | 운영 | 총괄 |
| 실기 조종 | ○ (ADR-002 §3) | × | × |
| 시뮬 | 띄우기·조종·시나리오 (ADR-002 §3.2) | «시뮬» 탭(§4) | 현재 단계 제외(배치·동선 짜기 등 후보, 미결 §10) |
| 하는 일 | 내 로봇 조종·시나리오·기록 | 시나리오·지도·기록·내 요청·개인 설정, 로봇 목록(내게 배정된 로봇만) | 결재·배정·로봇 현황 등(범위 미결) |
| STOP | 실기 STOP | 실기 STOP 없음. 시뮬 탭에 «시뮬 정지»(§6) | 없음. «정지 요청»(ADR-002 §5.3) |

- 총괄 페이지의 주소·기능 범위는 미결(§10). 그때까지 지금 PC 웹의 총괄 화면(결재함·계정·로봇 배정 설정)은 그대로 두고, 총괄 페이지가 생기는 단계(§7 ⑥)에서 운영 앱에서 뺀다.
- 운영 앱에 총괄 계정이 로그인하면 총괄 페이지로 안내한다. (제안, ⑥단계에서 적용)
- 권한 판정은 지금처럼 서버가 한다(AU-04). 앱을 나눠도 서버 권한 표는 화면이 아니라 서버에서 지킨다.

## 4. 웹 시뮬 («시뮬» 탭)

### 4.1 흐름
```
지도(월드)·시나리오 고르기 → 띄우기 → 보기·키보드 조종·시나리오 실행 → 끝내기
```

| 단계 | 하는 일 |
|---|---|
| 고르기 | 시뮬 월드에서 등록된 지도(층)와 그 지도의 시나리오 고르기. 시나리오는 «없음»도 가능 |
| 띄우기 | ADR-002 §6 시뮬 관리자에게 «로봇 넣기» 요청(관제 서버 거침). 1인 1대 |
| 보기 | 지도 위 로봇 위치·카메라·상태. 항상 «시뮬» 표시 |
| 키보드 조종 | 시뮬 로봇만(§4.2) |
| 시나리오 실행 | 고른 시나리오를 지점 차례로(§5). 진행·일시정지·이어서·중단 |
| 끝내기 | 0 + 조종권 반납 → 로봇 빼기 |

- 폰의 «시뮬 로봇 띄우기»도 같은 순서로 지도·시나리오를 고른다(결정 4). 시뮬러 선택(Gazebo/MuJoCo)과 «한 월드에 여러 로봇»은 ADR-002 §6 그대로.

### 4.2 키보드 조종 — 시뮬 전용
- 시뮬 로봇에만 열린다. 실기 로봇에는 PC 웹 조종 화면이 없다(ADR-002 §4 «조종 탭은 웹에서 뺀다» 유지).
- 키를 누르고 있는 동안만 움직이고, 떼면 0. 입력이 끊기면 deadman 0.3 s(SF-03) 그대로.
- 허용 범위는 에이전트가 보낸 범위표(시뮬 연속 구간, ADR-002 §8 10-22 후속 결정)로 자르고, 최종 판정은 에이전트다. 범위 밖 키(후진·옆 등)는 막힘을 표시한다.
- 키 배치는 02 F-TO-05 를 따른다. (제안)
- 조종권 규칙(1로봇 1조종자, 요청·넘김)은 ADR-002 §5.1 그대로.

### 4.3 시뮬 지도 — 월드에서 자동 등록
- 월드마다 층별 2D 지도(png + yaml)를 함께 둔다. 시뮬 관리자의 월드 목록에 등록되면 지도 탭에 층으로 올라간다. 원점·해상도가 월드 좌표와 같아 시나리오 좌표가 시뮬에서 그대로 맞는다.
- 다층 월드는 층마다 지도 하나. 층 연결점(계단 짝)은 지도 편집과 같은 자료로 둔다. (제안)
- 시뮬 지도는 «시뮬» 출처를 표시해 실기 지도와 섞이지 않게 한다. (제안)
- 자동 등록 지도는 결재 없이 승인(확정 10-23: «Gazebo 월드에서 자동으로 만든 시뮬 지도는 결재 없이 바로 승인»). 시뮬 출처를 표시하고 실기 로봇 배정·실행을 거부한다. 시나리오는 승인 판 위에서만 만든다(02 F-MS-02).
- 미리 만든 시나리오 몇 개를 월드와 함께 등록한다.
- 지도 원본·빌드 산출물은 공개 저장소에 넣지 않는다(08 §6). 월드 지도를 저장소에 둘 범위는 ②단계 작업에서 정한다.
- SLAM 으로 지도 만들기(MP-02, ADR-002 «빈 공간에서 지도 만들기»)는 나중.

## 5. 시나리오 실행 (1단계)

- 단위는 **시나리오**: 시작 지점까지 이동 → 지점 1 → 지점 2 … 차례로 Nav2 이동.
- 지점별 임무는 **표시·기록만**: 도착하면 «지점 n 도착 · 임무 이름»을 화면에 보이고 기록에 남긴 뒤 다음 지점으로 간다. 사진·대기·운영자 확인 같은 작업 동작은 다음 단계.
- 실행기는 **시뮬 먼저**. 실기 실행은 시뮬에서 통과한 뒤 붙인다(ADR-002 §8). 실행 단위·상태·지점 기록은 같은 계약을 쓰고, 실기 명령 경로는 아래처럼 ADR-002 §9 그대로다.
- 실행 상태·실패 이유 코드는 02 F-MS-06 을 따른다.
- 첫 실행기가 한 층 안만 다루는지(층 전환 F-MS-07 은 뒤로) 여부는 ⑤단계 계약에서 정한다.
- 실행 명령 경로:
  - **실기 = ADR-002 §9 그대로(확정)**: `run.start`·`run.control`·`run.confirm` 은 폰 → 에이전트. 이 ADR 은 바꾸지 않는다. 실행 계획 자료 전달 방식은 ADR-002 §9 대로 2단계 계약에서 정한다.
  - **웹 시뮬 = 미결(§10)**: PC 웹 «시뮬» 탭에는 폰이 없으므로 명령 경로(화면 → 서버 → 에이전트 / 화면 → 에이전트)를 ⑤단계 계약에서 정한다. 이 검토는 웹 시뮬에만 해당하고 실기 경로로 넓히지 않는다(§6.2).
  - 어느 경로든 §6 판정은 서버·에이전트가 한다.
- 시뮬 실행에 배정·결재·실행 전 점검(SF-12)을 그대로 거치는지는 미결(§10). 실기 실행은 기존 규칙 그대로.

## 6. 안전

바뀌지 않는 것: ADR-002 §7 전체(STOP 래치·자동 재개 없음·deadman 0.3 s·1로봇 1조종자·안전 Core 판정·상수·셀프테스트 기대값).

### 6.1 «폰 없는 자율 실행 금지» — 확정 (10-23)
ADR-002 §7 문구 그대로 확정하고, 시뮬에서 «조종자 폰» 자리를 무엇이 맡는지 정한다.

| | 실행을 지키는 연결 | 끊기면 |
|---|---|---|
| 실기 | **그 로봇 조종자 폰**의 현장 연결 | 0 + 목표 취소 + 잠금, 실행 «일시정지». 다시 붙은 뒤 사람이 «이어서» |
| 시뮬 | **실행을 건 화면**(PC 웹 «시뮬» 탭 또는 폰)의 연결 | 같음 |

- 끊김 판정은 ADR-002 §6 처럼 에이전트의 단조 벽시계로 잰다. 감시 시간 값은 계약에서 정하되 15 s 를 넘지 않는다(ADR-002 §7). 관제 서버 연결이 살아 있어도 멈춘다.
- 판정은 **서버·에이전트**가 한다. 화면은 상태를 보일 뿐이다. 화면이 «시뮬이다»라고 보내도 그 말로 규칙이 바뀌지 않는다.
- 시뮬인지 아닌지는 **에이전트의 simulation 설정**(에이전트 기동 때 명시하는 값)으로만 정한다. 서버 DB 값·화면 표시·로봇 이름으로 정하지 않는다.
- 이 규칙이 확정되었으므로 ADR-002 §8 2단계 선행 조건 «§7 관문 확정»은 채워졌다. 그래도 실행을 켜는 코드는 위 감시가 들어간 뒤에만 합친다.

### 6.2 웹 시뮬과 실기 경로 분리
- **«시뮬 정지»**: 웹 «시뮬» 탭의 정지 단추는 «STOP»이 아니라 «시뮬 정지»로 부르고 모양도 실기 STOP 과 다르게 한다. 동작은 STOP 과 같다(0 + 목표 취소 + 잠금, 자동 재개 없음). 실기 STOP 으로 오해해 «웹에서도 실기를 멈출 수 있다»고 믿지 않게 하려는 것이다. 늘 보이고 가리지 않는다.
- **실기 경로에 웹 시뮬 기능이 붙을 길 0**: 웹 시뮬의 띄우기·키보드 조종·실행 요청은 simulation 설정이 켜진 에이전트에서만 받는다. 두 겹으로 막는다. (구체 방식은 제안)
  - 서버: simulation 설정이 켜졌다고 보고한 에이전트(시뮬 관리자가 띄운 것)에만 웹 시뮬용 출입증을 내준다.
  - 에이전트: simulation 설정이 꺼져 있으면 웹 시뮬용 출입증·조종·실행 요청을 거부한다(서버 판정을 믿지 않고 다시 확인).
- 시뮬·실기 판정 경계를 바꾸는 코드는 08 §3 «안전 범위»(두 모델 검토)다.
- 새 시뮬 기동은 운영 시뮬과 다른 ROS 도메인·포트에서만, 첫 기동은 승인 뒤(08 §6, ADR-002 §6) 그대로.

## 7. 단계

| 단계 | 먼저 있어야 하는 것 | 결과 | 통과 기준 |
|---|---|---|---|
| ① | — | 지도·시나리오 탭 빈 곳 채우기: 운영자 «새 지도 올리기»(결재 요청, 서버는 이미 됨), 시나리오 목록의 배정 로봇·마지막 실행·«내 것/지도별» 거르기 | 운영 계정으로 올리기 → 결재 요청 생김, 목록 열·거르기 화면 확인 |
| ② | ①, §10 «자동 등록 지도 승인» 결정 | 시뮬 월드 ↔ 지도 자동 등록(월드 목록에 층·지도 판 연결), 미리 만든 시나리오 | 월드 하나 등록 → 지도 탭에 층으로 보임, 미리 만든 시나리오의 지점이 시뮬 좌표와 맞음 |
| ③ | ② + 시뮬 관리자 | 웹 «시뮬» 탭: 지도·시나리오 골라 띄우기·보기·끝내기 | 띄우기 → 위치·카메라·«시뮬» 표시 → 끝내기 → 로봇 빠짐 |
| ④ | ③ | 키보드 조종(시뮬 전용), «시뮬 정지» | 키 떼면 0, 입력 끊김 → 0 ≤ 0.4 s(ADR-002 1단계와 같은 기준), 시뮬 정지 뒤 재개 없음, simulation 설정 꺼진 에이전트는 거부 |
| ⑤ | ④ + §6.1 감시 | 시나리오 실행 API·Nav2 실행기(시뮬 먼저), 지점 도착 표시·기록 | 지점 차례 이동·도착 기록, 실행 건 화면 끊김 → 일시정지·잠금, 사람이 «이어서» 전엔 안 움직임 |
| ⑥ | §10 «총괄 페이지 범위» 결정 | 총괄 별도 페이지, 운영 앱에서 총괄 화면 빼기 | 총괄은 페이지에서 결재·배정·현황, 운영 앱은 운영 계정만 |

- ②~⑤는 ADR-002 §8 1·2단계와 겹친다. 폰과 웹이 같은 시뮬 관리자·에이전트 계약을 쓴다(웹 시뮬 실행 명령 경로만 §5 대로 ⑤단계 계약에서 정한다).
- 운영자 PC 로봇 범위(결정 2)는 결정이 나오면 작은 화면 작업으로 따로 한다.

## 8. 기존 문서와의 관계

이 ADR 과 다르면 이 ADR 이 우선한다. 01·02 본문은 후속 작업에서 고치고, 그때까지 아래 표가 가리킨다.

### 8.1 ADR-002 에서 대체되는 줄
| ADR-002 | 원래 | 바뀌는 점 |
|---|---|---|
| §1.1 | 앱을 «폰 조종 앱»과 «총괄 웹» 둘로 | 운영 앱(폰 + PC 웹, 운영 계정 전용)과 총괄 페이지(별도, 총괄 계정)로(§3) |
| §1.4, §4 | 총괄 웹에 STOP 없음 | 총괄 페이지에 STOP 없음은 그대로. 운영 PC 웹에도 실기 STOP 없음, 시뮬 탭에 «시뮬 정지»만(§6.2) |
| §4 표 | 총괄 웹 메뉴(로봇·결재·시나리오·지도·기록·설정)를 총괄·운영이 함께 | 운영 PC 웹 = 시나리오·지도·기록·내 요청·개인 설정·로봇(내게 배정된 로봇만)·**시뮬**. 결재·배정·로봇 현황·계정은 총괄 페이지(범위 미결) |
| §4 «조종 탭은 웹에서 뺀다» | 웹 조종 없음 | 실기는 그대로. 시뮬 로봇은 «시뮬» 탭에서 키보드 조종(§4.2) |
| §3.2 로봇 연결 | 시뮬 띄우기 = 지도(월드)·시뮬러 고르기, «빈 공간에서 지도 만들기» | 지도·시나리오 고르기(폰·웹). 빈 공간 지도 만들기는 나중 |
| §6 | 시뮬 요청은 폰이 관제 서버를 거쳐. 지도 = 월드 + 지도 짝, 지도 만들기는 시뮬 SLAM | 폰 또는 운영 PC 웹이 요청. 지도는 월드에서 자동 등록(§4.3), SLAM 나중 |
| §7 관문 | 2단계 전에 확정 | **확정(10-23)**. 시뮬은 실행을 건 화면 연결이 폰 자리(§6.1) |
| §8 2단계 선행 | «§7 관문 확정» | 채워짐. 시뮬 시나리오 실행은 이 문서 §7 ⑤ |
| §9 «명령 주인» `run.*` | 폰 → 에이전트 | **대체 아님.** 실기는 그대로. 웹 시뮬 실행 명령 경로만 보충, ⑤단계 계약 미결(§5) |
| §10 첫 줄 | §7 확정 — 미결 | 해결 |

## 9. 하지 않는 것 (이 결정 범위 밖)

- 총괄의 실기 조종, PC 웹 실기 조종.
- 로봇 배치·로봇별 시나리오(동선 짜기) — 나중, 총괄 페이지 쪽 후보.
- SLAM 지도 만들기, 지점 임무의 실제 동작 — 다음 단계.

## 10. 미결

| 항목 | 정할 때 |
|---|---|
| 운영 계정의 PC 웹 로봇 범위(내 로봇만 / 전체 보기 / 둘 다 토글) — 해결 | 내게 배정된 로봇만, 총괄은 전체(확정 10-25, 결정 2) |
| 총괄 페이지 주소·기능 범위(결재·배정·로봇 현황 외 무엇까지, 지도·시나리오 편집·시뮬 보기 포함 여부) | ⑥단계 전 |
| 총괄 페이지의 폰 접속 여부(운영 앱은 운영 계정 전용 — 결정 1) | ⑥단계 전 |
| 로봇 배치·로봇별 시나리오(동선 짜기)를 언제, 어디서(총괄 페이지 후보) | 팀 결정 |
| 시뮬 월드 자동 등록 지도의 결재·승인 처리 — 해결 | 결재 없이 승인(확정 10-23), 시뮬 출처 표시·실기 배정 거부(§4.3) |
| 시뮬 실행에 배정·결재·실행 전 점검을 그대로 거치는지 | ⑤단계 계약 |
| 웹 시뮬 실행 명령 경로(실기는 ADR-002 §9 확정), 첫 실행기의 층 전환 범위 | ⑤단계 계약 |
| 실행을 건 화면이 끊긴 뒤 다른 화면(같은 사람의 폰 ↔ 웹)에서 «이어서»를 받는지 | ⑤단계 계약 |
| 재접속 때 조종권 처리(새 조종권 취득·명시 해제·중립 입력 확인, ADR-002 §5.1) | ③·④단계 계약 |
| 다른 화면으로 실행 감시를 넘기는 조건(넘기는 동안 멈춤 유지 여부) | ⑤단계 계약 |
| 한 사람이 폰과 웹에서 동시에 시뮬을 띄울 때(1인 1대와의 관계) | ③단계 계약 |
| 공장 도면형·다층 월드 고르기 | 조사 뒤 |
