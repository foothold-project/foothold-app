## 1. 원문과 목적

팀장님 원문(2026-10-29, 그대로 인용):

> 「지킬 약속 다섯 줄」
> 1. 정책마다 관측 · 신경망 · 행동 변환 · 주기 · 정지 규칙을 한 묶음(정책 어댑터)으로 둡니다. 앱은 어댑터를 고르게 합니다.
> 2. 명령은 몸 기준 vx · vy · wz 입니다. 범위는 정책마다 다르고 위에서 자르지 않습니다.
> 3. 속도 명령을 내는 것은 한 번에 하나입니다(조이스틱 / Nav2 / HiPAN / 안전층 우선권).
> 4. 지도는 네 종류로, 각각 형식과 단위를 적어 둡니다. 2D 비용 지도에서 「벽」은 높이를 보고 정합니다.
> 5. 정지는 「명령 0」과 「잠금 정지」를 구분합니다. 몇 초 끊기면 무엇을 하는지도 정해 둡니다.

함께 온 요청:
- ① `policy_v2.f32` 출처(변환 스크립트·원본 sha256·같은 입력 출력 차이)
- ② 높이 187칸 평지 값(`mobile/sim/sim.js:99`) → 실제 발 앞 높이 측정
- ③ 안전 Core 가 정지·전진 0.6·전진+회전만 통과(`apps/agent/foothold_agent/safety/core.py:90-103` `quantize`) → vx·vy·wz 전부, 정책별 범위
- ④ 어댑터 셋: foothold-v2(속도 입력) / START 계열(조이스틱+임무, 깃발) / AME-2(임무 모드, 목표 위치+시간 입력)
- ⑤ AME-2 = 석헌 님 `model_14999.pt`, 정답 높이 지도·몸 속도를 받는 teacher → 시뮬 시연용

목적: 정책을 바꿀 때마다 앱·에이전트·시뮬 곳곳의 상수를 고치지 않도록, 정책 하나에 필요한 값을 **한 묶음(어댑터)** 으로 적고 앱은 그 id 만 고르게 한다. 이 문서는 약속과 현재 코드의 차이를 적는다. 구현은 §8 순서대로 별도 작업하며 P3 모바일 어댑터·높이 측정을 아래에 반영했다.

## 2. 어댑터 약속 (필드)

어댑터 하나는 아래 필드를 모두 가진다. 빠진 필드가 있는 어댑터는 앱이 고를 수 없다.

| 필드 | 뜻 | 예 (foothold-v2) |
|---|---|---|
| `id` | 앱이 고르는 이름. 소문자·숫자·`-` | `foothold-v2` |
| 관측 목록 | 항목 이름·순서·차원·단위·배율·clip. 합계 차원 | 235 = 몸 48 + 높이 187 |
| 신경망 | 파일 이름·sha256·형식(가중치 배열 순서·자료형·바이트 순서)·층 모양·활성함수 | `policy_v2.f32`, float32 LE, 4층 |
| 행동 변환 | 행동 개수·관절 순서·`목표각 = 기본 자세 + scale × 행동`·PD(Kp·Kd)·토크/속도 한도 | scale 0.25, Kp 25, Kd 0.5 |
| 주기 | 물리 dt·decimation·정책 주기 | 0.005 s × 4 = 0.02 s (50 Hz) |
| 명령 입력 | 종류(속도 / 목표 위치 / 목표+시간 / 조이스틱+임무)와 각 축 범위 | 속도 vx·vy·wz, 범위 §3 |
| 정지 규칙 | «명령 0» 때 신경망에 넣는 값, «잠금 정지» 때 하는 일(§7) | 명령 0 = (0,0,0) 입력 |

규칙:
- 앱(폰·웹 시뮬)은 **어댑터 id 로만** 정책을 고른다. 관측 순서·scale·PD 를 화면 코드에 따로 적지 않는다.
- 에이전트는 받은 id 의 어댑터가 선언한 **명령 범위**를 안전 Core 에 넘긴다(§4 계획).
- 같은 id 의 신경망 파일이 바뀌면 sha256 이 바뀌므로 새 id(또는 판 표시)를 쓴다.

P3 근거와 적용 범위:

- 앱은 `?policy=foothold-v2`(생략 시 같은 id)로 [어댑터](../../mobile/sim/policy-adapters.js)를 고른다. 관측 조립·신경망·행동·주기·명령 범위·정지 입력을 한 객체에 두며 START·AME-2는 등록하지 않는다. 기존 STOP 잠금·조종권·명령 제한 동작은 유지한다.
- 학습 설정 `foothold-lab/models/foothold-v2.env.yaml:354-385,630-667`: base에 붙인 RayCaster, 광선 시작만 z +20 m, yaw 정렬, size [1.6,1.0]·resolution 0.1·ordering xy, offset 0.5·miss 1·clip ±1. 설정 SHA-256 `a951ed5322428acc228fbd0b919dba5031af6bb567278edc763103a6a0f32292`.
- 평가 보관본 `gap_observations.py:69-80`: `sensor.data.pos_w.z − ray_hit_z − offset`, 유한 hit만 사용하고 나머지는 miss 값. SHA-256 `644d66fb128f0262ac24b12a716fb492c9ab97eede500f74d916d61cbfec2956`. 로컬 Isaac Lab `ray_caster.py:220-224,241-248,274-280`에서 +20은 광선 시작에만 더하고 `pos_w`는 몸 위치임도 확인했다. 구멍·미적중은 벽을 뜻하는 −1로 바꾸지 않는다. 외부 학습 코드는 읽기만 했다.
- 격자 순서 근거: 로컬 Isaac Lab 참조 `37ddf626871758333d6ed89cf64ad702aef127d0`의 `source/isaaclab/isaaclab/sensors/ray_caster/patterns/patterns.py:41-53`에서 `meshgrid(x,y,indexing='xy')`를 flatten한다. x가 빠른 11행×17열이며 index 0=(-0.8,-0.5), 16=(0.8,-0.5), 17=(-0.8,-0.4), 186=(0.8,0.5) m다. 참조 파일 SHA-256 `bf91f91b92d56b0beab13f6192fff051e8674fa83e1e516c377c886f27a9a26d`; 학습 당시 런타임 소스 자체의 판은 별도 미검증이다.
- MuJoCo `mj_ray`로 world body의 접촉 지형(group 0/1/4, 높이장 포함)을 읽는다. 로봇과 접촉 마스크가 모두 0인 라이다 전용 보수 상자는 제외한다. 이름 목록 `excludedGeomNames`는 제거했다. 필터를 위해 바꾼 geom group은 동기 스캔의 `finally`에서 복구하여 라이다·물리 호출 전에 원값이 된다. 움직이는 물체를 높이 입력에 포함하는 기능은 없다(학습도 `/World/ground`만 스캔).
- **학습과 다른 광선 시작 높이:** 학습은 지면 메시만 +20 m에서 스캔하지만, 앱 world에는 보·천장·조명이 함께 들어 있다. `h = base_z − hit_z − 0.5`를 ±1로 자르므로 포화 전 hit 높이는 `[base_z − 1.5, base_z + 0.5]`다. 앱은 시작을 `base_z + 0.501 m`(위 경계 +1 mm 여유)로 내려 그 위 형상은 이름 없이도 맞지 않게 한다. 이는 학습 지면 전용 스캔을 근사하는 기하 필터이며 같은 센서라고 주장하지 않는다. 낮은 머리 위 형상이 `base_z + 0.5` 아래까지 내려오면 지면과 구분하지 못해 장애물 값(−1 또는 그에 가까운 값)이 남는다. 시작점이 형상 안에 있거나 경사 지면이 시작 높이보다 높을 때도 지면 전용 스캔과 다를 수 있다.
- [높이 assert 시험](../../mobile/scripts/height-scan-selftest.mjs): 실제 로컬 MuJoCo로 평지=이전 상수·계단 앞 높이/부호·xy 순서·yaw·로봇/라이다 상자 제외·이름 없는 머리 위 보(base_z+1 m 이상) 무시·낮은 머리 위 형상 유지·group 복원·미적중·clip을 검사한다. `FH_SIM_SRC=<기존 로컬 시뮬 의존성> node mobile/scripts/height-scan-selftest.mjs`로 실행한다. 광선 시작 변경으로 몸이 지면 아래인 이전 clip−1 fixture는 미적중이 되므로, 같은 −1 기대값을 유지하면서 시작점 바로 아래의 평면으로 포화 입력을 만든다.

## 4. 명령 — 몸 기준 vx · vy · wz

약속: 명령은 몸 기준 vx(앞+, m/s) · vy(왼쪽+, m/s) · wz(왼회전+, rad/s). 범위는 정책마다 다르고 위에서 자르지 않는다.

### 4.1 현재 상태 — 실기는 기존 집합, 시뮬은 어댑터 범위

| 경로 | 통과하는 명령 | 근거 |
|---|---|---|
| 실기·기본(안전 Core `quantize`) | (0,0,0), (0.6,0,0), (0.6,0,±0.5) 네 개뿐. 후진·옆걸음·제자리 회전·저속은 0 + 이유 | `core.py:90-103` |
| 실기 화면에 알리는 범위 | `LIMITS` vx 0~0.6, vy 0, wz ±0.5, 위 네 명령 | `protocol.py:122-124` |
| 시뮬 Hub 폰·웹 입력 | foothold-v2: 정확한 (0,0,0) 또는 vx 0.4~1.5, vy 0, wz −1~1. 범위 안 SI 값 그대로, 밖·형식 오류는 0 + 이유. 클램프·양자화 없음 | `policy_ranges.py:28-57`, `protocol.py:85-98`, `hub.py:54-55` |
| 시뮬 Nav2 실행 | 이전 범위 유지: vx 0~0.6, vy 0, wz ±0.5(저속·제자리 회전 포함). simmgr 실행 증명·지도 연결이 맞을 때만 적용; 범위 밖·NaN·Inf·형식 오류는 0 + 이유 | `executor/nav2/simulation.py:81-114` |
| 시뮬 아닌 Hub 의 Nav2 | `quantize` (위 네 개) | `hub.py:82-83` |
| `mobile/sim` 단독 페이지 | 조이스틱 값 그대로 `sim.cmd`(안전 Core 없음, 시험 페이지) | `mobile/sim/main.js:64-65,289` |

시뮬 Hub 수동 입력의 정책 범위 정본은 `policy_ranges.py`의 어댑터 표다. `welcome.limits`의 기존 필드 값·의미는 그대로 유지한다(vx −0.3~1.0, 움직임 하한 0.2, vy ±0.3, wz ±0.5, `experimental`의 reverse·lateral·turn_in_place). 기존 폰은 이 입력 범위와 turn_in_place를 이용해 눌린 작은 입력을 비영으로 보존하므로, 이를 없애면 손 뗌 보호를 우회한다. 실제 허용 범위는 새 선택 필드 `policy_velocity_range`(vx 하한 0.4·상한 1.5, vy 0, wz ±1), `policy_adapter_id`, `requires_forward_motion`으로만 알린다. 기존 입력 범위가 실제 움직임 허용을 뜻하지 않으며, 수동 입력에서 전진 없는 회전·vy·후진은 에이전트가 0 + 이유로 거부한다(학습 standing은 세 축 모두 0, [DRIVE-MODES-VALIDATION](DRIVE-MODES-VALIDATION.md) «코드·설정 근거»).

시뮬 결정: 축별 `|v|<0.2` 데드존으로 허용된 회전값을 바꾸지 않는다. 전진 0<vx<0.4와 작은 비영 단독 입력은 0 + `UNSUPPORTED_VELOCITY`이며, 정확한 ZERO만 손 뗌을 확인한다. 안전 Core `cmd()`·`applied()`와 기본 Session의 ±1 축 검사는 그대로이며, `simulation is True`인 Hub만 SI 입력 검사를 사용한다. 범위 허용은 보행 검증을 뜻하지 않는다.

실기 불변 주의: 기존 Hub `project_velocity(.6,.2,0)`는 vy를 버리고 (.6,0,0)를 낸다. 이번에는 이 동작도 보존한다. (.3,0,0)·(0,0,.5)는 Hub에서 0 + 이유이며, 실기 Nav2 어댑터는 세 예제 모두 0 + 이유다. `quantize`·`LIMITS`·안전 셀프테스트 기대값은 변경하지 않았다.

화면 후속: 폰·웹은 같은 `apps/web/src/phone.ts:130-151`에서 vx 연속값을 보내지만 회전은 여전히 0·±상한으로 만든다. 새 범위를 이용한 연속 wz 계산과 작은 거부 입력 이유의 표시 빈도 조정은 화면 담당 후속이며 이번 작업에서는 수정하지 않는다. 시뮬 Nav2는 이전 범위를 유지한다. 정책 범위 적용은 Nav2 설정 변경(현민님 결정) 후 진행하며, 이번에는 제자리 회전을 끄거나 Nav2 설정을 바꾸지 않는다.

### 4.2 계획 — 범위는 어댑터가 선언한다 (시뮬 속도 범위는 §4.1 반영)

- 어댑터가 정책별 허용 범위(vx·vy·wz 최소·최대, 필요하면 막는 조합)를 선언한다.
- 안전 Core 는 **값을 다른 값으로 바꾸지 않는다.** 아래일 때만 0 으로 만든다:
  - 선언 범위 밖, NaN·Inf·형식 틀림
  - deadman(0.3 s 입력 끊김), 조종권 없음, 중립 확인 전
  - STOP 잠금, 재개·리셋 대기, 시뮬 상태 이상(지금 `applied()` 의 관문 그대로, `core.py:277-310`)
- 화면은 어댑터 범위를 받아 막대 → 속도를 계산한다(지금 `welcome.limits` 자리, `hub.py:350`).

### 4.3 관문 — 실기 Go2 에 새 범위를 쓰는 것

- 시뮬에서 어댑터 범위를 쓰는 것과 **실기 Go2 에 새 범위를 쓰는 것은 별도 승인 관문**이다.
- 실기 범위 변경은 ① 두 모델 검토(08 §3 안전 범위) ② 현민님 승인 ③ 범위마다 시뮬 보행 기록이 있어야 한다. 셋 전에는 실기 경로는 지금 `quantize` 를 유지한다.
- [09 ADR-002 §7](09-ADR-002-PHONE-DIRECT.md#7-안전) «안전 Core 판정·상수·셀프테스트 기대값은 바꾸지 않는다»는 그대로다. 정책별 범위 변경은 이 §4 관문으로만 한다.

### 6.1 2D 비용 지도의 «벽» = 높이 기준

| STOP 단추 | 즉시 | 0 + 목표 취소 + 잠금 | 잠금 정지 | 09 §7 |

- 실기 출력 감시가 걸린 뒤에는 새 입력만으로 다시 움직이지 않는다. hold 동안 새 apply 는 0 으로 바뀐다(`sink.py:85-87,265-266`). 풀리려면 ① 로봇 쪽 STOP 피드백(`stop_requested=true`, 같은 세대)이 와서 hold 를 풀고(`ros_bridge/node.py:153-154` → `sink.py:128-135`) ② 사람이 «STOP 해제»/«이어서»를 눌러 Session 관문(조종권·세대·Core 잠금 상태, `session.py:490-497`, `core.py:230-236`)을 지난 unlock 이 출력단에 닿고(`sink.py:91-98`) ③ 출력단이 hold 없음·같은 세대·최근 apply 를 확인해야 한다(`sink.py:250-262`). apply 감시만 걸리면 Core 는 잠기지 않아 해제가 «잠금 아님»으로 거절되므로(`core.py:233`) STOP 을 한 번 누른 뒤 해제한다(코드 읽기, 시험 안 함). 1분에 3번 멈추거나 2 s 안에 회복하지 못하면 출력 오류로 남는다(`sink.py:12-14,162-164,174-176`).
- 폰 연결 감시 끊김 → 0 + 목표 취소 + 잠금, 실행 «일시정지», 사람이 «이어서»([09 ADR-002 §7](09-ADR-002-PHONE-DIRECT.md#7-안전), 10-23 확정) 는 위 «폰 ping 3 s» 줄이 맡는다.
- 어댑터별 «명령 0» 때 신경망 입력: foothold-v2 = (0,0,0), AME-2 = `[0,0,0,1]`. AME-2 는 이것만으로 정지한다고 가정하지 않는다(§3).
- 실기 Go2 자체의 끊김 동작(내장 정지 시간 등): **미정** — 실기 관문 때 측정.

## 9. AME-2 교사 시연 어댑터 (실기 불가)

**실기 불가: 참 높이지도**를 읽는 교사 모델이다. 앱의 오프라인 MuJoCo 시연만 지원한다.
기본 정책은 계속 `foothold-v2`이며, 시뮬 메뉴의 정책 선택 또는 `?policy=ame2-demo`로
`AME-2(시연)`을 고른다. 선택 변경은 페이지를 새로 읽고 잠금 상태에서 시작한다.
AME-2에서는 기존 속도 기반 시나리오 실행을 끄고 두 막대만 사용한다.
실기 경로·Safety Core·서버·agent는 변경하지 않는다. 보행 성공은 평가하지 않았다.

### 9.1 입력과 출력

[출처 계약](../AME2-PROVENANCE.md)과 `mobile/scripts/ame2_export.py`의 NumPy 계산이 기준이다.
`ame2-network.js`는 CNN·ELU·공간 max·gaze hard crop·ties-to-even round·32-head MHA·출력 MLP를
새 의존성 없이 계산한다. 배치표의 41개 이름·shape·순서·offset·유한값을 확인하고,
브라우저 로더는 f32의 고정 SHA-256도 확인한다. `log_std`는 결정적 평균에 사용하지 않는다.

| 입력 | 0부터의 칸 / 순서 | 단위·처리 |
|---|---|---|
| 몸 49칸 | 0–2 선속도, 3–5 각속도, 6–8 중력 | 몸 좌표 m/s, rad/s, 단위벡터; 잡음 0 |
| 몸 49칸 | 9–20 기본각 대비 관절각, 21–32 관절속도 | rad, rad/s; 아래 정책 순서 |
| 몸 49칸 | 33–44 직전 raw 행동, 45–48 목표 | 직전 행동 ±50 clip; `[x,y,sin(yaw오차),cos(yaw오차)]`, m/무차원 |
| 지도 | `[29,13,3]`, x 바깥·y 안쪽·xyz | 6cm, x=−0.42…1.26m, y=−0.36…0.36m, yaw만 회전 |
| 지도 z | `clip(hit_world_z-body_z+0.27,-1.5,1.5)` | m; 잡음 0, 몸의 roll/pitch로 격자를 기울이지 않음 |
| 출력 | raw 평균 12칸 | `q_target=clip(q_default+0.25*a,-100,100)` rad |

PD는 Kp=25, Kd=0.5, 정책 50Hz/물리 200Hz다. 지연은 **고정 0 물리 step**으로,
학습 `delay_range=[0,4]`의 하한이다(받은 `params/env.yaml:1583–1600`,
`go2/ame2_go2/tasks/mdp/actions.py:52–60`). 관측 이력은 지연 목표각이 아닌 직전 raw 행동이다.
**시간 입력 미확인**: 독립 시간 칸이 보이지 않는다는 정적 관찰만으로 계약을 확정하지 않는다.

Go2HV 포락선은 `env.yaml:166–203`, `go2/ame2_go2/assets/unitree_go2.py:19–21,58–84`,
`go2/ame2_go2/assets/go2_curve.py:8–20`의 텍스트에 따른다. hip/thigh의 구동·제동 토크는
20.2/23.4Nm, 속도 평탄부/영점은 13.5/30rad/s다. calf는 감속비 `30.1/15.70`을 적용해
38.7273885/44.8624204Nm, 7.04152824/15.6478405rad/s다. 평탄부 이후 선형으로 줄인다.
MuJoCo XML의 별도 motor clamp가 이 포락선을 덮지 않도록 AME-2에서만 해제하며,
실제 actuator→joint 이름·gear=1을 검사한다. 기존 foothold-v2 모터 설정은 유지한다.

### 9.3 지형・조종·정지의 시연 선택

#178의 기하 필터를 `makeTerrainSampler`로 공유한다. world 충돌체만 읽고 로봇·라이다용
비충돌 proxy를 제외하며 group을 복원한다. 광선은 `body_z+0.501m`에서 내려 머리 위 형상을
제외한다. 학습의 +20m top-down과는 다르며, 낮은 선반·여러 층의 지형 의미는 미확인이다.

무반사는 받은 `observations.py:110–140`에서 이번 설정의 virtual-floor 분기를 확인하고,
`go2/ame2_go2/sensors/virtual_floor.py:56–83`의 규칙을 사용한다. 앱 지도에는 학습 타일의
가상 바닥 표식이 없으므로 가상 평면은 끈다. 무반사 칸은 최저 유효 세계 높이−depth,
전부 무반사면 floor_z−depth로 채운 뒤 상대높이 변환·clip한다. depth는 잡음 없는 시연을 위해
`env.yaml:1793–1799`의 −1.0…−0.4m 중간값에 해당하는 **0.7m 고정 가정**이다.
학습의 타일별 가상 평면·에피소드별 난수를 재현한다는 뜻은 아니다. 구버전
`min_valid+U(-1.5,-0.65)` 분기와 혼동하지 않는다.

조종은 계획 A안이다. 왼쪽 위 방향은 몸 앞 0…1m, 좌우는 옆 목표이며 전체 목표 거리를
1m 이하로 정규화해 2m 미만을 유지한다. 뒤 입력은 앞 거리를 0으로 제한한다.
오른쪽 막대는 목표 heading을 최대 1rad/s로 적분하고 현재 yaw 대비 ±60°로 제한한다.
완전 중립은 목표·heading을 현 자세에 붙여 `[0,0,0,1]`이다. STOP·앱 숨김·blur·pagehide·freeze는
목표·이전 행동을 버리고 기존 잠금을 유지하며 AME-2 정책·물리를 일시정지한다.
다시 시작은 기존 버튼만 가능하고 막대를 새로 눌러야 한다. 중립 입력이 물리적 정지를
보장한다고 가정하지 않는다. reset·정책 변경도 AME-2를 잠근다.

### 9.4 자산 배포와 검증

가중치·배치표·check.json은 커밋하지 않는다. `sync-web.mjs`가 기존 `FH_SIM_SRC`에서
foothold-v2 자산을 복사하고, 선택적 `FH_AME2_SRC`(미지정 시 `FH_SIM_SRC`)에서
`ame2_actor.f32`·`ame2_actor.json`을 **둘 다 있을 때만** `www/sim`에 복사한다.
없으면 AME-2 선택지가 비활성화되고 이유가 표시된다. 없는 모델을 URL로 요청해도
foothold-v2 잠금 상태로 돌아간다. 모델 로드 오류는 이유를 표시하고 실행하지 않는다.
APK 생성·배포는 이번 작업에 포함하지 않는다.

- `AME2_EXPORT=<로컬 내보내기 폴더> node mobile/scripts/ame2-network-selftest.mjs`: 274건,
  JS↔NumPy 최대 절대 차 **5.364418029785156e-6**, crop offset 전부 동일, 유한값 검사 통과.
- Node **22.23.3**, CPU 측정: 단독 측정 첫 추론 46.09ms, 중앙값 19.38ms, p95 25.02ms.
  폰 시간이 아니며 20ms 실시간 예산을 보장하지 않는다.
- `FH_SIM_SRC=… AME2_EXPORT=… node mobile/scripts/ame2-sim-selftest.mjs`: 높이 최대 오차
  **1.668930060816365e-8m**(≤1mm), 평지·경사·계단·yaw·roll/pitch·무반사·기하 제외 통과.
  평지 3초/150회 정책 추론·600회 물리 step에서 NaN·예외 없음. 보행 성공 판정 없음.
- `height-scan-selftest.mjs`, `height-walk-selftest.mjs`(기준 a840fe2), `start-selftest.mjs`,
  `scenario-selftest.mjs`, `top-fit-selftest.mjs`: 모두 통과. 기존 5개 지도/각6초의
  foothold-v2 낙상 0, 기준과 같은 이동 거리. 기존 안전 시험 기대값은 변경하지 않았다.
- `FH_PLAYWRIGHT=<기존 playwright-core/index.mjs> node mobile/scripts/ame2-ui-selftest.mjs`:
  headless Chrome·임의 로컬 포트에서 모델 부재·기본 정책·선택·중립·STOP·pagehide·자동 재개 없음 통과.

남은 미확인: 실제 USD 관절 순서, 시간 입력 계약, 원래 학습 actor 실행과의 일치,
MuJoCo/PhysX 접촉 차이, 라이선스·재배포 범위, 실폰 속도·발열, 실기 센서 지도, 보행 성능.
