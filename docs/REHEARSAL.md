# 리허설 계획과 지도 편집

이 기능은 현장 도면을 옮기고 여러 로봇의 배치를 준비하는 도구다. 계획 작성·2D 기하 검토·세계/지도 파일 생성은 실제 Gazebo 주행이나 실 Go2 연결의 성공을 뜻하지 않는다.

화면 구조는 지정 Claude 디자인 세션의 [고정 설계](DESIGN-FLEET-20261018.md)를 따른다. 구현 검수에서 확인한 차이·판단·미측정은 작업 기록의 `USER-NOTES.md`에 누적한다.

## 화면과 제어 경계

- `#/Fleet`: 계획 로봇과 현재 연결된 단일 대상을 구분해 보는 전체 관제 입구.
- `#/MapEditor`: 층·벽·상자·계단·로봇 출발 위치·센서·장비·경로·배치안을 편집한다.
- `#/Field`: 휴대폰에서 고른 대상의 현황·지도·보고·기록으로 들어간다.
- 기존 `#/Main`, `#/MDrive` 등 조종 화면은 유지한다. 새 프로젝트를 고르거나 저장해도 조종권을 얻거나 기존 연결 대상을 바꾸지 않는다. 계획 대상에 실기 명령을 보내지 않는다.
- STOP은 기존 연결 경로의 단일 대상에 적용된다. 계획의 로봇 이름이나 배치안을 실제 제어 주소로 사용하지 않는다.

## 프로젝트 자료

정본 JSON 형식은 `fh_rehearsal_scene/1`이다. 단위는 m·rad, 세계 원점은 xy, 층 높이는 z, 지도 해상도는 0.05 m이다. 도면의 픽셀 좌표는 오른쪽/아래 방향이며 두 쌍의 기준점으로 세계 좌표와 연결한다.

요청·응답의 형식과 상세 검증 규칙은 [API 계약](CONTRACT-rehearsal.md)에 있다.

`/api/rehearsal`은 기존 로그인 관문을 경유한다. APK에서는 동일한 네이티브 세션의 `/api/app/rehearsal`만 사용한다. GET은 메타 목록, POST는 `list/get/put/delete/analyze/export`만 허용한다. 로봇 제어·Gazebo 기동 작업은 이 API에 없다.

자료는 `<media>/rehearsal`에 보관한다. 기존 임무 문서·사진·사건·시작 원장과 별도다. 수정은 읽은 `rev`와 서버 판을 대조하며 충돌은 409로 반환한다. 삭제는 보관함 이동이며 기존 판을 자동 정리하지 않는다. 코드 되돌리기는 프로젝트 자료 삭제를 의미하지 않는다.

요청 256 KiB, 응답 1 MiB, 내보내기 ZIP 원본 640 KiB가 상한이다. 이미지·세계 크기·층·요소·경로·계산 시간에도 서버 제한이 있다. 큰 도면은 편집 화면에서 축소·압축하며, 상한 때문에 저장/계산이 거부되면 원본 초안을 유지한다. 실패·시간 초과는 저장이 전혀 없었다는 증거가 아니므로 목록과 판을 다시 확인한다. 자동 덮어쓰기·자동 재시도는 하지 않는다.

## 생성물의 뜻

내보내기는 고정 저장 판에서 정적 `world.sdf`, 층별 `map.pgm/map.yaml`, 설계 출처, 배치·이름공간 계획, 파일 hash manifest를 만든다. 세계와 지도는 동일한 기하에서 생성된다. 도면 배경은 벽이나 장애물이 아니며 따라 그린 요소만 기하가 된다.

계단은 상자 단으로 표현하고 위층 도착 부분을 개구부로 만든다. 치수 입력 상한은 자원/형식 제한이며, 로봇이 오를 수 있음이 검증된 치수 범위가 아니다. 층 지도는 2D 투영이므로 계단 주행·층 전환·다층 경로를 증명하지 않는다.

로봇·센서 배치는 계획 값이며 실제 드라이버/보행 정책/장착을 바꾸지 않는다. 현재 생성된 세계에는 다중 Go2와 제어기가 자동 스폰되지 않는다. `plan.json`의 이름공간·토픽도 기동된 연결이 아니다. 파일을 만들었다고 기존 시뮬 시작 목록에 등록하거나 Gazebo를 실행하지 않는다.

기하 검토의 경로 길이·장애물 통과·같은 층 연결·선분 교차는 물리 리허설 결과가 아니다. 넘어짐·소요 시간·통신 음영·센서 사각·실제 도달은 측정 자료가 있을 때만 판단한다. 새 도면과 실제 위치의 좌표 정합이 확인되기 전에는 둘을 같은 지도 좌표라고 가정하지 않는다.

## 브랜드와 미확인

공식 FOOTHOLD 토큰/로고와 Pretendard를 사용한다. 계획/미확인/실패를 색과 문구로 구분하고, 예시 숫자를 실제 상태로 쓰지 않는다.

Go2 기종/SDK 접근, L1/L2 최종 기준, 계단 주행 확인 치수, 다중 실연결, 지도 정합·Nav2·실폰 전체 흐름은 별도 확인 대상이다. 기존 앱 STOP은 하드웨어 비상정지나 본체 정지 보장이 아니다.

## 개발 검사

UI 검증 환경은 Node 22다. `ui/`의 `npm test`와 `npm run build`를 사용하며, 시스템 Node 18에서 장착 시험의 `navigator` 환경 오류가 생기는 경우와 제품의 단언 실패를 구분한다. JSON 시험 입력은 `ui/tests/fixtures/rehearsal/`에 포함한다. 서버의 순수 검사는 `tests/backend/test_rehearsal.py`와 `tools/rehearsal_{link,proxy,scope}_check.py`이며, 임시 저장소·로컬 시험용 HTTP를 사용한다. 이 검사 명령은 ROS/Gazebo 기동을 대신하지 않는다.
