## 이 기준을 선택한 근거

- 기존 통합 출처 문서가 웹 `98242c7`과 모바일 `a8c3da7`의 결합을 기록한다.
- 운영 웹 R34 교체 기록은 `98242c7` 기준으로 상태 점검 49/49 통과를 기록한다. 소스·단위·화면 검토 기록의 검사 범위와 승계 한계는 기존 기록을 따른다.
- APK15는 이 통합판과 같은 `ui/`·`mobile/` 소스로 빌드됐으며 APK 구조 대조 28항목 통과가 기록되어 있다. APK 바이트 SHA-256은 `f09b0e8009aad2160ac0985cd3db2e0c7ffb377d1510fd46b05a8636e224c4a3`이다.
- 이번 작업에서는 과거 앱 검증을 재실행하지 않는다. 코드 트리 동일성, 브랜치 관계, 문서·변경 경로, 공개 대상과 Git 반영 상태를 확인한다.

출처: [기존 통합 출처와 검증 한계](PROVENANCE-app-platform-integration.md). 로컬 원시 운영 기록은 공개 Git에 추가하지 않는다.

## 보장하지 않는 범위

- 위 검사는 실제 APK 실행·실폰·WebView·실 로그인·iOS·실 Go2 연결 성공을 뜻하지 않는다.
- 자동 이동·자동 촬영·자동 복귀·자동 도착 판정과 조직별 권한 관리가 완성된 판이 아니다.
- 진행 중인 등록부·다중 로봇 권한·연결 전환 변경은 미커밋 작업이므로 최초 기준에서 제외한다. 기능 브랜치에서 완성하고 `dev`에서 검증한다.
- 이번 전환은 Supabase 도입, 서버 이전, 자동 배포, 기존 서비스 재시작 또는 새 APK 배포가 아니다.

## 작업 폴더와 원격 설정

- 기존 웹·모바일·통합·운영 worktree의 HEAD와 미커밋 파일을 바꾸지 않는다.
- 설명 세션의 기존 폴더에도 내용이 다른 미커밋 파일이 있으므로 자동 checkout을 하지 않는다. `main` / `dev`의 생성과 현재 폴더의 브랜치 전환은 별개다.
- 저장소 관리자 권한이 없어 GitHub 기본 브랜치와 보호 규칙은 직접 바꿀 수 없다. 관리자 설정 항목은 [작업 규칙 7절](GITHUB-WORKFLOW.md#7-github-관리자-설정과-전환-상태)에 적는다.
