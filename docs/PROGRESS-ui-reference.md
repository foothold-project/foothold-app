# 시안 그대로 UI 구현 — 진행 기록

기준: 디자인 시안 10개 화면을 원본 그대로 구현합니다. 기능 연결은 UI를 확정한 다음에 합니다.
화면 속 값은 모두 예시 데이터입니다. ROS·실제 로봇·실제 임무와 연결되어 있지 않고, STOP 버튼은 모양만 있는 시안입니다.

## 2. 구현 방식

- `web/<화면>.dc.html` = 원본 파일 그대로입니다. 바꾼 곳은 두 가지뿐입니다.
  - 실행 스크립트 3줄(react, react-dom, support.js)을 `<script src="./dc.js">` 1줄로 바꿨습니다.
  - 사용자가 승인한 수정(아래 4절).
- `web/dc.js` = 직접 만든 실행기(React 없음). 시안 10개에 쓰인 문법만 지원합니다:
  - `{{경로}}`
  - `sc-if`, `sc-for`
  - `on*` 이벤트
  - `setState`
- 원본 실행기와 동작을 맞춘 점:
  - 글 속 값은 `span.sc-interp`로 감쌉니다. 이 차이로 flex 간격이 달라집니다.
  - null과 true/false는 그리지 않습니다.
  - `<select value>`는 해당 항목을 고릅니다.
  - 값이 바뀌면 커서를 끝으로 옮깁니다.
  - 원본은 SVG `<text>` 안의 값을 그리지 못했습니다. 구현은 승인 수정으로 그립니다(4절).
- `web/index.html` = 화면 목록과 «예시 데이터» 안내입니다.

## 4. 원본과 다른 점 — 사용자 승인 수정 (10-12)

현민님이 「이 3건만 수정」과 「공개용 예시 문구로 변경」을 확정했습니다. 그 밖의 배치·색·글꼴·이미지는 원본 그대로입니다.

| 승인 | 바꾼 곳 | 내용 |
|---|---|---|
| 1 지도 글자 | `web/dc.js` | SVG 안의 `{{값}}`을 span 대신 SVG 글자 요소 `tspan`으로 감쌉니다. 원인이 실행기 공통이라 화면 파일은 그대로 둡니다. |
| 2 틀 밖 문단 | `web/Main.dc.html` | 화면 틀 밖의 «분야는 미정이다…» 문단과 남는 `</div>`를 지웠습니다. 이 문장은 아래 「제품 지침」으로 옮겼습니다. |
| 3 STOP 오른쪽 위 | `web/Main.dc.html` | 머리줄을 한 줄로 고정했습니다(`flex-wrap:nowrap`, 항목은 줄지 않음). 상태 칩 묶음만 줄어들어 그 안에서 줄바꿈합니다. 칩 내용은 숨기지 않습니다. |
| 3 STOP 스크롤 고정 | Main · PcMissions · PcPlan · PcReview | 머리줄에 `position:sticky; top:0; z-index:10`을 줬습니다. 스크롤해도 STOP이 화면 위에 남습니다. 휴대폰 화면은 바꾸지 않았습니다. |
| 4 예시 이름 | Main · PcMissions · PcReview · Report | 원본의 예시 운영자 이름을 «운영자 A»로, Main 머리줄 머리글자를 «A»로 바꿨습니다(원본 값은 비공개 `reference/`에만 있음). |
| 4 예시 기준 | Report · Main | Report에서 법규 조항·해외 기준 준용·법정 보존 기간을 뜻하던 문구 3곳과 Main 가스 타일 LEL 설명 2곳(해외 기준 준용)을 «예시 기준 · 검증 전»으로 바꿨습니다. 기준값 주석은 «표의 기준값은 예시 기준 · 검증 전입니다. 실제 적용 기준이 아닙니다.»입니다. |

- 1의 적용 범위: 10개 화면 가운데 SVG 안에 `{{값}}` 글자가 있는 곳은 Main 5곳뿐입니다(지점 이름 3, 태그 표시 1, θ 1). PcPlan 지도 글자는 원래 고정 글자라 그려지고 있었습니다(차이 0).
- 승인 범위 밖이라 그대로 둔 기준 문구:
  - PcMissions «법정 기준 대비 측정표»
  - System «법정 기준 초과»
  - Report·PcReview «적정공기 기준(10 ppm 미만)», «적정 기준»
  - 모두 화면 속 예시 문구입니다. 실제 적용 기준이 아닙니다.

**제품 지침 (Main 원본에서 옮김)**: 분야는 미정이다. 단계마다 다음 기준이 정해지지 않은 임무는 실행하지 않는다: 이동, 확인, 작업, 개입, 실패, 결과.

## 5. 미결 — 사용자 결정 전까지 원본 그대로 둡니다

- **Q1 조종 막대 배치**
  - 시안 기본값은 «왼쪽 이동(앞뒤·옆) · 오른쪽 회전»입니다.
  - 기존 요청은 «왼쪽 회전 · 오른쪽 앞뒤»였습니다.
  - 시안에는 두 배치가 모두 있습니다(`?stickLayout=`). 기본값은 바꾸지 않았습니다.
- **Q2 예시 기능을 계속 예시로 둘지**: 5초 통신 끊김 후퇴, 가스·AI·긴급 경보.
  - 문구와 배치는 그대로 두었습니다.
  - 실제 기능으로 연결하지 않았습니다.
- RGB 차이가 16 이하인 픽셀은 세지 않았습니다. 그래서 위 결과를 픽셀까지 완전히 같다는 뜻으로 쓰지 않습니다.
- **링크 빈자리 (`href="#"`)**
  - PC 4개 화면에는 왼쪽 메뉴의 아직 없는 항목이 각각 3개씩 있습니다. Main에는 «기준 설정» 1개가 더 있습니다.
  - MHome에는 2개 있습니다.
  - 지도·로봇·설정 같은 하위 화면은 시안에 없어서 만들지 않았습니다. 앞으로 만들 기능으로 남깁니다.
- 글꼴을 오프라인에 둘지, `reference/`를 저장소에 넣을지(support.js 라이선스), 저장소 라이선스: 모두 미정입니다.

## 6. Git

- 원격: 비어 있는 공개 저장소입니다. AGENTS·CONTRIBUTING·.github·템플릿 없음, rulesets `[]`, 라이선스 없음.
- 이 계정의 권한은 pull만 있고 push는 없습니다.
- 브랜치 `feature/ui-reference-oh`에 로컬 커밋만 합니다. 이 저장소에만 작성자를 GitHub noreply 주소로 설정했습니다(전역 git 설정은 그대로).
  - push와 PR은 권한, 실제 GitHub 규칙, 최종 내용 검수가 모두 갖춰진 뒤에 합니다.
  - main에 직접 push하거나 force하지 않습니다.
- 커밋 대상: `web/`, `tools/`, `docs/`, `README.md`, `.gitignore`. 제외: `runs/`, `reference/`.
