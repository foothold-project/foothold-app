# SLAM pipeline server/agent contract

The mapping pipeline is Point-LIO live + GLIM final. Unitree built-in SLAM commands and subscriptions are not used by this mapping path. This server never executes robot commands or systemd; the agent implements the lifecycle behind a local switch that is disabled by default.

## Sources and service lifecycle

`apps/contracts/mapping_sources.py` owns source assumptions. MappingSource is point_lio/glim; legacy retains the old PCD protocol only for compatibility. Point-LIO defaults: registered scan `/cloud_registered`, pose `/aft_mapped_to_init`, user service `foothold-pointlio`. GLIM: final cloud/pose topics are deliberately unset pending investigation; service `foothold-glim`. Configurable environment names are FH_MAPPING_POINT_LIO_CLOUD_TOPIC / ODOM_TOPIC / SERVICE and FH_MAPPING_GLIM_CLOUD_TOPIC / ODOM_TOPIC / SERVICE (each full name repeats the prefix). FH_MAPPING_SERVICE_CONTROL_ENABLED defaults false; only the explicit value true enables the adapter switch. Agent installation and approval are separate from this server PR.

Start means the agent starts both configured `systemd --user` services. Save means obtain GLIM final data, compute and upload the 5 cm voxel/grid pair, then stop both services. No guessed GLIM topic or save method is provided. Registered Point-LIO scans may support ray tracing only with the matching timestamped sensor origin and pose; do not ray trace an accumulated cloud with the current pose. The server stores agent-computed cells and does not calculate rays.

## Commands and revision transitions

POST /robots/{robot}/slam/start defaults source=legacy when source is omitted, preserving current web/r24 agent compatibility. Omitted source and explicit legacy both send exactly `{t, op, session_id, floor_id}` for start/save/cancel and use the old PCD upload path. Only explicit source=point_lio opts into the new pipeline; supply floor_id and optionally one name. Only the authenticated robot owner starts/saves. Pipeline commands preserve op/session_id/floor_id and add pipeline=point_lio+glim, source, final_source=glim, command_id, requested_at, revision. Never replay start on reconnect. Movement approval/leases are independent. A new pipeline web consumer must explicitly send source=point_lio.

The pipeline start accepts only the live source point_lio; source=glim returns 400 without normalization. The explicit legacy value remains solely for old PCD compatibility. GLIM is final_source only until an operator save request permits the new-revision handoff.

One session owns the pipeline; ownership binds to session_id, not source. progress.source is constant within each revision. Live revisions use point_lio; once GLIM rebuild completes, a newer revision switches atomically to source=glim, a reset voxel chunk in its frame and GLIM odom. Clear all old voxel/grid/tile/pose state on revision changes. Same-revision source mixing and glim to point_lio rollback return 409. A failed final rebuild keeps the last Point-LIO revision with a reason. Global update_seq increases across the entire session; voxel seq increases independently within its revision.

Status/phase: STARTING/START_REQUESTED, RUNNING/STARTED, SAVING/SAVE_REQUESTED, FINALIZING/SLAM_SAVED, UNKNOWN/UNKNOWN, FAILED/FAILED. Only server bundle persistence creates SAVED or RECEIVED_ONLY. SAVED requires bundle slam_save=SLAM_SAVED; RECEIVED_ONLY means the received files were retained without confirmed SLAM save. Both are terminal, allow a new session, and retain immutable geometry and manifest completeness. `slam_save` is SLAM_SAVED / UNKNOWN / FAILED and describes the GLIM save outcome separately from file persistence. Matching late acknowledgements may update this outcome without replacing artifacts, promoting RECEIVED_ONLY, approving its map, or enabling terrain. Bundle source must equal the last accepted revision source; Point-LIO received-only fallback cannot claim SLAM_SAVED final geometry.

## Live observations and recovery

POST /agent/robots/{robot}/slam/{session}/progress accepts JSON up to 65,536 bytes. WebSocket slam.update has the same limit; other frames retain 4 KiB. Echo command_id, revision, monotonic update_seq and source. Voxel delta: revision, seq, reset, frame_id, resolution=.05, integer XYZ added/removed (at most 2,000 changed cells); cell lower corner = index*.05 metres. First chunk/new revision requires reset. Split byte-bounded chunks, oldest pending change first.

HTTP progress retains 403/409 permission/source rejection responses. The WS slam.update handler discards only that observation on these rejections and keeps the agent socket open for control, STOP and state. The session's server-owned `last_report_rejection={code,reason,received_at}` records the last rejected WS observation; repeated identical code/reason pairs leave it unchanged. Recording is scoped to the matching organization/robot/session/floor, including legacy sessions. Agents cannot overwrite this diagnostic. Agent authentication/token failures still close the connection through the existing authentication gates.

`tiles` has at most four MappingGridTile entries per report: revision, tile_seq per coordinate, x/y tile coordinates, frame_id, floor_z, size=64, resolution=.05, exactly 4,096 uncompressed row-major cells from bottom left (0 unknown/1 free/2 occupied). Tile lower left = [x*3.2,y*3.2] metres. x/y=-3125..3124, at most 4,096 retained tiles/session. SQL retains newest tile_seq; a new revision discards old tiles. Whole grid snapshots remain compatible under the same report byte limit.

GET /robots/{robot}/slam/{session}/tiles?revision=R&cursor=0&since=0 returns four tiles, update_seq and opaque next_cursor. Follow cursors until null. Catch up changes during the read with cursor=0 and since=the first page update_seq of the prior pass; compare per-tile sequence numbers. Revision mismatch is 409; clear and restart. Browser places tiles, with no map calculation.

### Durable live voxel recovery

The agent report format is unchanged. `GET /robots/{robot}/slam` still exposes only the last `voxels` delta for compatibility; use the paged endpoint below to recover every currently occupied cell after multiple reports. SQL `mapping_voxel_states` retains revision/frame, maximum voxel seq, latest reset seq and occupied count; `mapping_voxels` retains each cell's latest actual change seq and occupied/removed state. Reports commit geometry and progress together under the existing organization lock. Duplicate coordinates are counted once, removals precede additions (an overlapping addition wins), and adding an already occupied cell does not change its last-change seq. At most 500,000 cells may be occupied, matching the bundle limit. Overflow rejects the whole report with HTTP 409 `MAPPING_VOXEL_LIMIT`, preserves the preceding geometry/progress and records server-owned `last_report_rejection` for both REST and WS; WS retains the control connection. Removal tombstones survive until reset or a newer revision so arbitrarily late incremental readers can recover deletions. Reset clears all prior cells/tombstones; a newer revision also clears all previous voxel state even if its first report has no voxels. SQL state survives server restart.

All paths below start with `/api/v1`. Voxel reads use the same current-robot-owner, organization, real-floor and archive gates as tiles; they do not require an agent connection. Responses have `Cache-Control: private, no-store`.

| API | Query / response |
|---|---|
| `GET /robots/{robot}/slam/{session}/voxels` | Required `revision=R`; optional `since=S` (default 0, **revision-local voxel seq**, independent of progress/tiles `update_seq`), opaque string `cursor=C` (omit on first page). |
| `MappingVoxelPage` | `session_id`, `revision`, `seq` (current maximum voxel seq), `reset`, `reset_seq`, `resolution=.05`, `frame_id`, `added`, `removed`, `next_cursor`. Each change is `{cell:[x,y,z],seq}` with its last actual change seq. At most 512 total changes and 65,536 UTF-8 JSON bytes per page. |
| Recovery | Begin with `since=0`, no cursor. Follow `next_cursor` unchanged until null, retaining the same revision and since throughout the pass. Results are latest cell states, not an event log. Full reads return occupied cells only. To catch changes during paging, start another pass without cursor and `since=the first page seq of the prior pass`; apply per-cell seq without regressing newer changes. |
| Reset | `reset=true` when `since=0` or `since < reset_seq`: clear client cells **once at the start of that pass**, then assemble all its pages as a new full state. The flag is repeated on every page; do not clear for each page. An empty reset still carries its new seq/reset_seq. Before any accepted voxel chunk the page is empty with seq/reset_seq=0 and frame_id=null. |
| Conflicts | Revision mismatch: 409 `MAPPING_REVISION_CONFLICT`. Reset after a cursor was issued: 409 `MAPPING_VOXEL_RESET_CONFLICT`; clear and restart without cursor/since. A since greater than current seq: 409 `MAPPING_VOXEL_SEQUENCE_CONFLICT`; restart from since=0. Malformed cursors or cursor/session/revision/since binding mismatch: 422 `MAPPING_VOXEL_CURSOR_INVALID`. |

Pages are bounded keyset reads, not frozen snapshots. Coordinates modified behind a cursor are recovered in the catch-up pass, using its first-page baseline and per-cell seq. Reads take the same organization lock as reports so reset metadata and selected cells cannot come from different resets. Cursors remain usable after restart and must be treated as opaque by clients.

Migration 0034 only adds the live voxel tables and role grants; it does not rewrite historical sessions, deltas, maps or bundles. Pre-upgrade sessions with only a last delta cannot be reconstructed: the voxel endpoint returns 409 `MAPPING_VOXELS_RESET_REQUIRED` until the agent sends an accepted reset chunk/new revision. A non-reset chunk for such a session is rejected with the same recorded reason. The agent wire protocol and automatic agent behavior are unchanged, so recovering an already-running pre-upgrade session may require restarting map acquisition. Downgrade refuses while either live voxel table contains data; code rollback can retain these additive tables without deleting evidence.

MappingOdom is provider, source topic, frame_id, raw stamp={sec,nanosec}, XYZ/yaw and optional display_stamp. The selected adapter validates its configurable topic. Pose must match its revision source/frame; no odometry substitution or cross-device latency inference. Geometry and storage have no hard-coded frame names.

## Paired persistence and optional terrain

POST /agent/robots/{robot}/slam/{session}/bundle accepts MappingBundle JSON up to 50 MiB: session_id, source, revision, frame_id, resolution=.05, at most 500,000 XYZ voxels, complete grid with at most 4,000,000 cells and dimensions <=4096, optional matching odom, slam_save and times. Grid includes origin=[x,y,0], floor_z, frame_id, resolution, dimensions and row-major states. Both artifacts share source/revision/frame. Hash covers geometry, source and contents; acknowledgement state is separate. Retry identical contents; conflicting hash/revision/source is 409.

With an operator save_requested_at, UNKNOWN or FAILED status/phase still accepts received data with slam_save=UNKNOWN or FAILED. The session becomes RECEIVED_ONLY, reason says SLAM 저장 확인 안 됨 · 받은 범위만 보관했습니다, and manifest completeness=RECEIVED_ONLY. Its MapVersion is PENDING with a pending approval request, and the floor's approved_version_id and existing approved map remain unchanged. No terrain converter is called; terrain_id is null and terrain_status=SKIPPED_UNCONFIRMED_SAVE. This does not claim a complete final map. Without save_requested_at it is 409. SAVED means confirmed SLAM save plus both files and DB snapshot committed, manifest completeness=SLAM_CONFIRMED. Cancel, changed owner/token/base are rechecked after receiving/encoding, before publication. Migration 0033 adds RECEIVED_ONLY without rewriting historical rows; downgrade refuses while such rows remain.

Authenticated GET /robots/{robot}/slam/{session}/bundle returns manifest and optional terrain link; /bundle/voxels is little-endian int32 XYZ triples, /bundle/grid is one state byte/cell. MapVersion.slam_bundle links source session/robot/map, source/revision and save/completeness snapshot for historical reopening. Same-annotation-raster checks guard inherited links.

The existing CELL=.1 terrain converter remains unchanged. Terrain generation follows only a confirmed paired save in a separate transaction; failure keeps both maps SAVED. Session linkage records the generated floor/map, native-to-terrain translation and crop/geometry warnings. It is a standalone environment, not an exact same-raster mission twin. Identical confirmed bundle retry can retry terrain without replacing maps. A RECEIVED_ONLY retry or late SLAM_SAVED acknowledgement never triggers conversion or automatic approval; the persisted completeness snapshot controls eligibility.

MappingTimes preserves UTC server receipt, start/save request, forwarding, agent receipt/publication, SLAM acknowledgement, first/last data and saved timestamps; start/save forwarding/ack are retained separately. Agent cannot override server times. Diagnostics exclude credentials, addresses and raw point contents. Raw source stamps are not used to infer latency.

Hardware installation, service startup/stop, Point-LIO input timing/frame transforms, GLIM topics/save method and actual simulation execution remain unverified. No remote host, robot or simulator was contacted.
