# Built-in SLAM server/agent contract

`POST /robots/{robot}/slam/start` defaults to `source: unitree_uslam`; `legacy` retains the old PCD acquisition path. Name is provided once on start. Only the authenticated robot owner may start/save; observation upload authenticates the robot independently of motion approval. No server endpoint grants a motion lease or enables DDS output.

`slam` commands retain op/session_id/floor_id. Built-in commands also carry source, command_id, requested_at and revision. Do not replay start on reconnect. Echo command_id and phase in progress. Phases: START_REQUESTED, STARTED, SAVE_REQUESTED, ROBOT_SAVED, UNKNOWN, FAILED. Server starts in STARTING, accepts RUNNING only with STARTED, and owns SAVING/FINALIZING/SAVED. Timeout/ambiguous robot responses remain UNKNOWN.

Agent status/phase pairs: STARTING/START_REQUESTED, RUNNING/STARTED, SAVING/SAVE_REQUESTED, FINALIZING/ROBOT_SAVED, UNKNOWN/UNKNOWN, FAILED/FAILED. SAVING and FINALIZING require an operator save request; only bundle persistence may create SAVED. A matching late robot save acknowledgement can update robot_save after SAVED without replacing either map. Bundle hashes cover map content/geometry/revision; robot acknowledgement status is separate. A prior UNKNOWN robot response does not prevent preserving the requested two maps.

Progress POST: `/agent/robots/{robot}/slam/{session}/progress`, JSON at most 65,536 bytes (also the WebSocket slam.update limit; other WebSocket frames retain 4 KiB). Built-in progress requires monotonic update_seq, revision and current command_id. Voxel updates carry revision/seq/reset/frame_id, fixed .05 resolution and added/removed integer XYZ cell indices (at most 2,000 total changes). Lower corner = index × .05 metres, world axes, no server translation. First voxel update/new revision requires reset. Split changes into byte-bounded reports, oldest pending change first.

Live 2D uses `tiles: MappingGridTile[]` (at most four per report): each has revision, tile_seq (monotonic per tile), x/y tile coordinates, frame_id, floor_z, size=64, resolution=.05, and exactly 4,096 cells. Uncompressed row-major cells from bottom left, 0 unknown/1 free/2 occupied. Tile lower left in metres = [x*3.2,y*3.2]; axes are world axes. x/y range -3125..3124, at most 4,096 retained tiles/session. Server retains newest tile_seq for each coordinate; new map revision discards all prior tiles. Duplicated/older tile_seq does not overwrite a newer tile. The final bundle still uses the complete grid (origin [x,y,0], width/height, floor_z, frame_id, revision); grid snapshots in progress remain compatible subject to the report byte limit.

Reconnect/full tile read: `GET /robots/{robot}/slam/{session}/tiles?revision=R&cursor=0&since=0`. Response MappingTilePage has at most four tiles, update_seq, revision and next_cursor (opaque integer; use unchanged). Repeat until next_cursor=null. Catch up changes that arrived while reading with cursor=0 and since=the update_seq from the **first** page of the prior pass, then repeat; per-tile sequence numbers make overlaps harmless. A revision mismatch returns 409; clear old tiles and restart. The browser only places received tiles. Persistent SQL tile storage survives server restart; movement approval is never required to read it.

Odom source is exclusively /uslam/frontend/odom. `MappingOdom.stamp` is the raw ROS `{sec: integer, nanosec: integer}`; preserve it exactly, with optional display_stamp UTC for display only. Neither value is used to infer transport latency. Odom also carries frame_id and XYZ/yaw; no substitution from other odometry.

Final upload: `POST /agent/robots/{robot}/slam/{session}/bundle`, MappingBundle JSON at most 50 MiB, at most 500,000 XYZ voxels and 4,000,000 grid cells (dimensions ≤4096). revision/frame must match across both results. robot_save is ROBOT_SAVED/UNKNOWN/FAILED independently of server storage success. Retry identical contents/revision after failure; a conflicting revision/hash is rejected. SAVED means both artifacts committed. Terrain generation follows separately; terrain failure leaves both maps SAVED.

MappingTimes uses UTC timestamps for server_received_at, command_forwarded_at, agent_received_at, command_published_at, robot_ack_at, first_data_at, last_data_at and saved_at. Server also retains start_requested_at/save_requested_at, start_forwarded_at/save_forwarded_at and start_ack_at/save_ack_at separately. Server-owned timestamps cannot be overwritten by agent reports. Logs/diagnostics contain timestamps/counts/status only, never credentials, addresses or point contents. Cross-device clock differences are not reported as measured latency.

Stored artifacts are available through authenticated `GET /robots/{robot}/slam/{session}/bundle` (manifest and optional terrain link), `/bundle/voxels` (little-endian int32 XYZ triplets) and `/bundle/grid` (one state byte per cell, bottom-left row first). The immutable map Upload metadata also retains session_id, geometry, native coordinates and hashes. Terrain linkage lives on the session because Upload rows are immutable; it includes the separate simulation floor/map identifiers, source proof, source_translation and conversion warnings. This standalone generated environment uses the existing 10 cm converter's bounded/cropped terrain geometry; it does not claim an exact same-raster mission twin of the native 5 cm map. Repeating the identical bundle retries failed optional terrain generation without replacing the saved maps.

The legacy global terrain CELL=.1 remains unchanged; bundle storage preserves .05 cell indices and the supplied 2D grid. Actual firmware/DDS command support, sensor frames and on-robot save behavior require a separately approved hardware test.
