# FOOTHOLD 로봇 컴퓨터 설치 묶음

설치 절차와 제한은 `apps/agent/JETSON-ONBOARD.md`를 따릅니다.
설치 자체는 연결 프로그램이나 서비스를 시작하지 않습니다.

처음에는 설치된 `~/foothold-robot/venv/bin/python -I ~/foothold-robot/launch.py`를
실행하고, 상태 화면에서 랜선이 연결된 로봇을 확인한 뒤 웹에서 한 번 등록합니다.
내부 유선 NIC(이름·MAC), 로봇 MAC, 컴퓨터 고유값의 해시를 비공개
`private/agent.json`에 인증과 함께 저장합니다. 다음 시작에서 모두 일치하면
확인을 생략합니다. 하나라도 다르거나 컴퓨터 고유값을 읽지 못하면 사람 확인을
기다리며 조종을 잠급니다. 노트북 설치는 매번 확인합니다.

**부팅 · 로그인 자동 시작은 하지 않습니다** (팀장 11/19 · 22:16 자동으로 떠 로봇 명령을 낼 수 있었음).
서비스 파일에 `[Install]` 칸이 없어 `enable` 이 되지 않습니다. 사람이 로봇 곁에서 손으로 켭니다.

연결 서비스 켜기 (지금 한 번): `sh ~/foothold-robot/start-service.sh`

연결 서비스 끄기: `sh ~/foothold-robot/stop-service.sh`

켜기는 사용자 서비스 `~/.config/systemd/user/foothold-robot.service`를 등록하고
`start` 만 합니다. 예전 설치가 `enable` 해 둔 연결이 있으면 먼저 `disable` 로 지웁니다.
끄기는 `disable --now` 후 해당 서비스 파일만 지웁니다.
sudo·시스템 서비스·linger 설정은 사용하지 않습니다. 재부팅하면 꺼진 채로 있습니다.
실패하면 STOP·잠금·소켓 정리 후 0 아닌 코드로 끝나고 20초 뒤 다시 시도합니다.
600초에 5회 제한에 도달하면 멈출 수 있습니다. 원인을 확인한 뒤 켜기 스크립트를
다시 실행하면 실패 제한을 초기화합니다. 사람이 기체 확인을 기다리는 상태는 실패가 아닙니다.

실행 기록: `~/foothold-robot-run.log` (계속 덧붙임).
기록 크기는 운영자가 관리합니다.

로봇을 옮겨 달거나 랜선을 다른 Go2에 꽂기 전에는 서비스를 끄고 등록을 다시
확인해야 합니다. **같은 MAC을 보내는 다른 기체를 같은 Jetson·같은 NIC에 연결하면
이 묶음으로는 구별할 수 없습니다.** MAC은 고유한 기체번호나 암호학적 신원이 아닙니다.
MAC 파생 번호로 다시 등록하면 항상 새 기록이 생기며, 기존 기록 재접속은 저장 인증으로 합니다.
전원 켜짐은 조종 허용이 아닙니다. 기존 서버·조종권·STOP·잠금 해제 조건은 그대로 적용됩니다.
